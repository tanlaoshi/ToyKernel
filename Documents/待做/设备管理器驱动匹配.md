## 一、目标与硬约束

### 目标

1. 定型 **`DRIVER_MATCH`**（PCI / DTB / FIXED），终结 `TOY_DRIVER.Match` 的 `void *` 占位。  
2. 框架提供 **`DriverMatchesDevice`（名可微调）**；有表则先匹配再 Probe。  
3. **最多迁 1 个驱动做验证**（建议 demo，可选再迁 xhci-hid）；其余 `Match = NULL` 仍走旧自扫。

### 硬约束

| # | 约束 |
| - | ---- |
| 1 | **不改**现有驱动行为（`Match==NULL` 时路径与今相同） |
| 2 | **不改** `Device.h` / `Driver.h` 现有 API **签名**（只扩展类型与字段语义） |
| 3 | **不改** `Probe` 三参数签名：`(Self, BusCtx, OutPrivate)` |
| 4 | 新逻辑 ≤300/文件；可拆 `DriverMatch.c` |
| 5 | 每刀可编译 + smoke；**勿**一次迁全部驱动 |
| 6 | **不**占文首 ★，除非明文改 ★ |

### 明确不做

- ❌ 强制 AHCI/NVMe/e1000/virtio 全部改 Match  
- ❌ 用「设备×驱动双重循环 + 新 Probe(Dev)」推翻现网分阶段 ProbeClass  
- ❌ 本柱完成真正多实例/每设备一 Instance（现框架一驱动一实例）

## 二、现状锚点（分析）

### 2.1 `Include/Driver.h` · `TOY_DRIVER`

| 字段 | 现状 |
| ---- | ---- |
| `Name` / `Class` | 有 |
| **`Match`** | 已有 `const void *Match`；注释「D2+ 占位」；**全树均为 NULL/0** |
| `Probe` | `int (*)(const TOY_DRIVER *Self, void *BusCtx, void **OutPrivate)` |
| `Bind` / `Remove` | 有 |

→ 任务书新增 `Matches` **应落在现有 `Match` 上定型**，避免双字段；类型改为 `const DRIVER_MATCH *`（或保留 void* 外加 typed 访问宏——推荐直接改类型，初始化处写 `0` 仍合法）。

### 2.2 `Common/Library/Driver.c`

- `ToyDriverProbeClass`：按类过滤 → 已有 Instance 则跳过 → **`Probe(D, 0, &Private)`** → Bind。  
- **从不读 `Match`**；`BusCtx` 恒 `0`。  
- `ToyDriverProbeAll` = `ProbeClass(NONE)`（全类）；启动路径 **刻意不用** early ProbeAll（防 PS/2 等过早）。

### 2.3 `DEVICE_NODE` / Bind

- 设备表在 `DeviceEnumerateAll` 之后已就绪（早于 `HalDriverRegister`）。  
- `DeviceBindDriver` **仍无调用方**；表内 `Bound`≈0。  
- 「已绑定」观感仍以 `ToyDriverInstance` 为准（见阶段 1 策略 A）。

### 2.4 `InputXhci.c`

- `gXhciInputDriver.Match = 0`。  
- Probe **内部** `PciScanUSBControllers`，按 ProgIF=xHCI 自扫；**忽略 BusCtx**。  
- 成功依赖 VMM/HID 就绪；由 Usb 模块择机 `ToyDriverProbeClass(INPUT)`。

### 2.5 驱动清单（均无 Match 表）

约 14 个已注册 `TOY_DRIVER`（ahci/ata/nvme/msc、xhci-hid、ps2、e1000、virtio-*、demo…）。  
私有 ID 表仅见 e1000 侧 `gE1000Ids`（未挂 `Match`）。

### 2.6 启动顺序（关键）

```text
DeviceInitialize → DeviceEnumerateAll
  → HalDriverRegister
  → ToyDriverProbeClass(BLOCK)     /* 仅 Block；非 ProbeAll */
… 稍后 …
  Input / Net / 再 Block：各自 ProbeClass
```

设备列表 **先于** 首次 Probe 存在；但 Probe **尚未消费**设备表。

## 三、Agent 思考（相对任务书校正）

### 3.1 不要照抄任务书里的 `ToyDriverProbeAll`

任务书示意：

```c
for 每个 Dev:
  for 每个 Drv:
    if Match: Probe(Drv, Dev); DeviceBindDriver(...)
```

与现网冲突：

| 点 | 风险 |
| -- | ---- |
| Probe 签名 | 现为三参；不是 `Probe(Drv, Dev)` |
| 双重扫描 | xhci/ahci/e1000 Probe 内已扫 PCI → 再按 Dev 调会重复/乱序 |
| 分阶段 ProbeClass | 过早 ProbeAll 曾导致键鼠问题；**保持按类、按模块时机** |
| 一驱动一实例 | `DriverAlreadyBound` 跳过；多控制器不映射 |

**推荐框架行为（兼容）**：

```text
ToyDriverProbeClass(Class):
  for 每个已注册且类匹配的 Drv:
    if 已有 Instance: skip
    if Drv->Match == NULL:
      Probe(Drv, 0, &Priv)          /* 旧路径 */
    else:
      for 每个未绑定 Dev:
        if !DriverMatchesDevice(Drv, Dev): continue
        Probe(Drv, Dev /*as BusCtx*/, &Priv)
        成功则可选 DeviceBindDriver(Dev, Drv, Inst); break
```

- `Match==NULL`：**零行为差**。  
- `Match!=NULL`：把匹配到的 `DEVICE_NODE *` 经 **`BusCtx` 传入**（文档约定）；驱动可选用或仍自扫。

### 3.2 验证驱动选谁

| 候选 | 利 | 弊 |
| ---- | -- | -- |
| **demo-driver（推荐第 3 刀）** | 无硬件、无自扫；易证明 Match→BusCtx→Bind | 课上无「真键鼠」体感 |
| **xhci-hid（任务书）** | 真输入验收 | Probe 复杂；易双扫；须 NUC+QEMU；改动面大 |
| e1000 | 已有 `gE1000Ids` 可搬 | 网卡时序/多 DID；非最小 |

**建议**：第 3 刀先 **demo**；若课要输入故事，再单开「xhci Match 迁移」刀（仍保留自扫回退：BusCtx 空则旧逻辑）。

### 3.3 `Match` 字段命名

- 沿用 **`Match`**（单数指针指向 `DRIVER_MATCH[]`，以 `TYPE_NONE` 结尾）。  
- 任务书 `Matches` 作同义文档名即可，避免改遍所有驱动初始化器字段名以外的噪音——实际只改类型。

### 3.4 PCI 掩码约定

```text
VendorMask / DeviceMask：位与后相等即命中
精确匹配：Mask = 0xFFFF
「任意 Device」：DeviceMask = 0（实现时写清；或 Device=0 且 Mask=0）
```

xhci 若只写两个 DID，**漏掉 QEMU 其它 xHCI DID** → 键鼠挂；故 xhci 迁移须列齐课用 DID **或** Class 匹配扩展（本柱可不做 Class 匹配，留阶段 3）。

### 3.5 与阶段 1 关系

- 阶段 1：观察面友好名 / BAR size。  
- 阶段 2：驱动↔设备匹配框架。  
- `DeviceBindDriver` 在 Match 成功路径调用后，阶段 1 策略 B 才开始有意义；策略 A 仍可并存。

### 3.6 `Driver.c` 行数

匹配逻辑建议 **`Common/Library/DriverMatch.c`** + `Driver.h` 声明，避免 `Driver.c` 胀破 300。

## 四、PR 拆分（3 刀）

| 序 | PR（建议名） | 交付 | 验收 |
| -- | ------------ | ---- | ---- |
| **1** | **PR-DRV-match-type** | `DRIVER_MATCH` / `DRIVER_MATCH_TYPE`；`TOY_DRIVER.Match` 定为 `const DRIVER_MATCH *` | 全驱动仍 `Match=0`；build + smoke |
| **2** | **PR-DRV-match-logic** | `DriverMatchesDevice`；`ToyDriverProbeClass` 分支；成功可选 `DeviceBindDriver` | Match=NULL 路径回归；可用 demo 或单测桩验证有表路径 |
| **3** | **PR-DRV-match-demo**（推荐）或 **xhci** | 一个驱动填表 + 文档一句 | demo：Probe 见到非空 BusCtx；或 xhci：QEMU(+NUC) 键鼠 + lsdev |

**依赖**：1 → 2 → 3。  
**勿**在刀 2 改所有驱动。

### 第 1 刀 · 类型

```c
typedef enum {
    DRIVER_MATCH_NONE = 0,
    DRIVER_MATCH_PCI,
    DRIVER_MATCH_DTB,
    DRIVER_MATCH_FIXED
} DRIVER_MATCH_TYPE;

typedef struct DRIVER_MATCH {
    DRIVER_MATCH_TYPE Type;
    union {
        struct {
            UINT16 Vendor;
            UINT16 Device;
            UINT16 VendorMask;
            UINT16 DeviceMask;
        } Pci;
        struct {
            char Compatible[64];
        } Dtb;
        struct {
            UINT64 Base;
        } Fixed;
    } U; /* 或匿名 union；避免与 C 关键字冲突按仓库风格 */
} DRIVER_MATCH;
```

`TOY_DRIVER.Match`：`const DRIVER_MATCH *`（NULL = 旧行为）。

### 第 2 刀 · 逻辑

- 实现匹配；**ProbeClass 保持按类、按调用时机**。  
- `Match==NULL` → `Probe(Self, 0, …)`。  
- 有 Match → 遍历 `DeviceGet`；命中则 `Probe(Self, (void *)Dev, …)`；成功 `DeviceBindDriver`。  
- 文档：`BusCtx` 对 Match 驱动为 `DEVICE_NODE *`。

### 第 3 刀 · 验证驱动

**推荐 demo-driver**：

- 表可含一条永不命中的 PCI + 一条匹配「任意已枚举 PCI」（慎用）或匹配 QEMU 宿主桥教学 DID。  
- 更干净：FIXED/测试用 Compatible；或仅当 `DeviceCount()>0` 时 Match 第一张 PCI 网卡——实现时选**可重复**条件。  

**若坚持 xhci-hid**：

- 表列齐课用 DID；Probe：**若 BusCtx≠NULL 则只试该设备 BAR**，否则回退 `PciScanUSBControllers`。  
- 验收：QEMU 键鼠；NUC 另测；勿删旧扫描直到 NUC 绿。
