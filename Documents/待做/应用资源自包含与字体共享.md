## 一、目标与硬约束

### 目标

| 代号 | 含义 |
| ---- | ---- |
| **方案 B** | 应用 = 目录包（借鉴 macOS bundle 思路，元数据仍用 `PKG.TXT`，不用 plist） |
| **方案 C** | 系统字体共享；应用默认不管字体；可选私有字体 |

### 目标目录（安装后 · app）

```text
Apps/<id>/
├── PKG.TXT           # 元数据（安装时写入或从仓库拷入）
├── <file>.ELF        # 可执行（静态链接；无 .a/.so 运行时依赖）
├── Assets/           # 应用私有资源（icon / data / 可选私有 .fnt）
└── README.md         # 可选
```

### 硬约束

| # | 约束 |
| - | ---- |
| 1 | 保持现有 `PKG.TXT` 键值格式（**不**引入 plist） |
| 2 | 私有资源目录名保持 `Assets/`（**不**引入 `Resources/`） |
| 3 | 用户 ELF **静态链接**；**不**引入 Guest 动态库产品路径 |
| 4 | 系统字体仍在 `TOYOS:/Assets/Fonts/`（共享） |
| 5 | 应用私有字体（若有）在 `Apps/<id>/Assets/` |
| 6 | 干净卸载 app = 删整个 `Apps/<id>/` |
| 7 | 新 `.c` ≤300 行；按「1 核心 + 多辅助」拆 |
| 8 | **每步**独立可编译、可 smoke；**勿**一次做完 4 步 |
| 9 | **不**破坏现有 `font` / `asset` / `lib` 扁平安装语义（本柱主改 **type=app**） |
| 10 | **不**占文首 ★，除非明文改 ★；与 PR-S-job / K-preempt **解耦** |

### 明确不做

- ❌ plist / JSON 包格式

## 二、现状锚点（分析 · 2026-09-22）

> 对应任务书「先分析」条目；确认后再开第 1 步。

### 2.1 StoreInstall / StoreRemove

| 点 | 现状 |
| -- | ---- |
| app 落点 | **扁平** `Apps/<file>`（如 `Apps/GUIDEMO.ELF`） |
| font | `Assets/Fonts/<file>` |
| asset/lib | `Assets/Packs/<file>` |
| 源查找 | `StoreCache/<file>` → `Assets/Store/packages/<id>/<file>` → 卷根 `<file>` |
| DB | `si.<id>=type\|file`；`sd.<id>=depends` 或 `-` |
| Remove | 按 `si` 的 `file` 在对应目录 unlink 单文件 + 清 `si`/`sd`；字体触发 `FontReloadAssets` |
| Combo | `StoreComboPlan*` + 每包 `StoreInstall`/`StoreRemove`（PR-S-job-phases） |

**缺口（相对方案 B）**：无 `Apps/<id>/`；无整树拷贝；无递归删目录。

### 2.2 PKG.TXT / catalog

| 点 | 现状 |
| -- | ---- |
| catalog | `id\|type\|version\|file\|sha256\|arch\|title[\|depends]` |
| PKG 运行时解析 | **仅** `depends=`（覆盖 catalog 第 8 段）；`name=`/`file=`/`title=` 等多为样例文档 |
| 未用字段 | `desktop` / `taskbar` / `icon` / `font` / `category` **均未进** `STORE_ENTRY` |

### 2.3 FAT / FileSystem

| 能力 | 现状 |
| ---- | ---- |
| `FileSystemMakeDirectory` | 有；**单层**；父目录须已存在 |
| `FileSystemRemoveDirectory` | 有；**仅空目录** |
| 递归 mkdir（MakePath） | **无** |
| 递归删树 | **无** |
| WriteFile | 不自动建父目录 |

→ 第 1 / 4 步前须先具备（或本柱内先交付）`FileSystemMakePath` + `FileSystemRemoveTree`（名可微调）。

### 2.4 应用如何读资源

| 点 | 现状 |
| -- | ---- |
| GuiDemo | ToyUi 演示；**不**读 BMP/私有 Assets |
| 依赖包 | `guidemo` → `demopack`（Packs）+ `sun8`（Fonts）— **共享依赖**，非 app 目录内 |
| 系统图标 | 桌面硬编码 `Assets/Icons/bmp48/*.BMP` |

### 2.5 字体 / ToyGfx

| 点 | 现状 |
| -- | ---- |
| 内核 | `FontLoadAssets` / `FontReloadAssets` 扫 `Assets/Fonts/*.FNT`（TOYF） |
| Store font 安装 | 置 `gNeedFontReload` → Flush 时重载 |
| `User/Library/ToyGfx` | 损伤/填充/绘制 syscall；**无**「加载字体文件」API |
| 用户态文本 | 走内核已选字体；应用**已经**多数「不管字体路径」 |

→ 方案 C 对 ToyGfx 更像 **文档化 + 薄封装**（`ToyGfxInitialize` 保证/声明用系统字），而非从零实现字库加载。私有字体若要做，需另定 User API 与内核加载入口。

### 2.6 Desktop / 开始菜单

| 点 | 现状 |
| -- | ---- |
| 桌面图标 | **硬编码**（Shell/Settings/Files/Store/Devices + `SNAKE.ELF` 等） |
| 开始菜单 Apps 区 | **非递归**扫 `Apps/*.ELF`；目录项跳过 |
| Store 字段驱动 | **无**；不读 `desktop=` / `taskbar=` / `icon=` |

→ 方案 B 后若 ELF 在 `Apps/<id>/`，**现网菜单会看不见**，第 3 步必须跟上（或 Install 期间写兼容 junction——不推荐，宁改菜单）。

### 2.7 TOYOS.DB

| 键 | 用途 |
| -- | ---- |
| `si.<id>` | `type\|file`（file 现为**基名**） |
| `sd.<id>` | depends |
| （提案）`sx.<id>` | desktop/taskbar 等注册 |
| （提案）`sy.<id>` | icon 相对路径 |

`si.file` 若改为 `id/FOO.ELF` 或仅存基名 + 约定根在 `Apps/<id>/`，须与 Remove / Managed / Menu **同一约定**。

## 三、Agent / 设计思考（纳入规格）

下列为对照现状后的取舍，避免实现时踩坑。

### 3.1 只改 app，font/asset 仍扁平

- **font** 继续装到 `Assets/Fonts/`（方案 C 共享面）。  
- **asset/lib** 继续 `Assets/Packs/`（或多 app 共享资源包）。  
- **app** 才进 `Apps/<id>/`。  
这样「系统字共享」与「应用自包含」不打架；`sun8` 仍可作 depends，也可将来 app 自带私有 `.fnt`。

### 3.2 双轨兼容（迁移）

现网已有 `Apps/GUIDEMO.ELF`、菜单扫扁平 ELF、`si.file=GUIDEMO.ELF`。

建议：

| 策略 | 说明 |
| ---- | ---- |
| **新装 app** | 一律 `Apps/<id>/` |
| **旧扁平** | Remove/菜单/Managed **仍认** `Apps/<file>`（无子目录）；或首次 Store 迁移刀扫一遍搬入 `<id>/` |
| **禁止** | 静默只认新布局导致旧盘「已装却菜单空」 |

第 1 步验收须含：旧盘扁平 app 仍能 Remove / exec。

### 3.3 `si.file` 语义

推荐（实现时二选一，写进 PR 验收）：

- **A（推荐）**：`si.file` 仍为 ELF **基名**；根目录约定 `Apps/<id>/`；Menu/Remove 拼 `Apps/<id>/<file>`。  
- **B**：`si.file` 改为相对 `Apps/` 的路径 `id/FOO.ELF`；Managed/菜单全改比较。

A 对旧代码冲击更小。

### 3.4 仓库包形态

`Assets/Store/packages/<id>/` 已接近 bundle 源：

```text
packages/<id>/
  PKG.TXT
  <file>.ELF
  Assets/...    # 新增约定：整树拷到 Apps/<id>/Assets/
```

Install = **建 `Apps/<id>/` + 拷 ELF + 拷 PKG.TXT + 递归拷 Assets/**（不是只拷一个 file）。  
`file=` 仍指出主 ELF 名。

### 3.5 demopack / depends 与私有 Assets

- **共享资源**（多 app 共用说明包、字库）：继续 `type=asset|font` + `depends=`。  
- **仅本 app 数据/图标**：放进该 app 的 `Assets/`，**不必**再做一个 demopack 依赖。  
- GuiDemo 课路径可渐进：先 `icon=` + 私有 Assets；`sun8` 仍 depends 系统字，体现方案 C。

### 3.6 与 PR-S-job

- Job 相位/chunk **不**改变「装到哪」；本柱改的是 **落点与删树**。  
- 整树拷贝更久 → 更依赖 job-chunk；可本柱 Step 内继续 `StoreIoBreath`，大拷贝切片留给 job-chunk。  
- **勿**在同一 JX 揉「改布局 + chunk 可重入」。

### 3.7 ToyGfx「自动加载系统字体」

现状内核已加载 `Assets/Fonts`。方案 C 落地宜：

1. 文档：应用 `ToyGfxInitialize` / 首绘前字体已由内核就绪。  
2. 可选：User 库增加无操作或探测 API，避免课上误以为要 `FontLoad("...")`。  
3. 私有字体：另刀；需内核支持「按路径加载 TOYF」再挂到窗/任务——**不要**塞进第 1 步。

### 3.8 桌面 vs 开始菜单

- `desktop=yes` → 桌面图标（现硬编码表要改成「固定系统项 + Store 动态项」）。  
- `taskbar=yes` / 菜单 → 开始菜单动态项（现扫扁平 ELF 要改）。  
- 系统项（Shell/Settings/…）**永远**固定，不被 Store 覆盖。

### 3.9 vvfat / 真机

递归删 + 多文件写在 QEMU vvfat 上易触发映射断言（装卸柱已见）。验收以 **IDE/raw 盘或真机** 为准；vvfat 仅作冒烟辅助。

### 3.10 FAT 递归 API 归属

`FileSystemMakePath` / `RemoveTree` 放 `FileSystem/` 或 `Fat/`，**独立小 PR** 可先于或并入第 1 步序 0；勿藏在 StoreInstall 里复制两套。

## 四、目标 PKG.TXT（扩展字段 · 仍键值）

```text
name=mygame
type=app
version=1
file=MYGAME.ELF
sha256=-
arch=x86_64
title=My Game
depends=

desktop=yes
taskbar=yes
icon=Assets/icon.bmp
# font=Assets/myfont.fnt   # 可选；不填 = 系统字
category=game
```

| 字段 | 含义 | 缺省 |
| ---- | ---- | ---- |
| `desktop` | 是否上桌面 | `no` |
| `taskbar` | 是否进开始菜单（命名可保留 taskbar） | `no` |
| `icon` | 相对 **应用目录** | 无则用系统默认图标 |
| `font` | 相对应用目录的私有字 | 无则系统字 |
| `category` | 预留分类 | 空 |

catalog 行可暂不扩列；**以安装后 PKG / DB 为准**（与现 `depends` PKG 覆盖策略一致）。

### 第 1 步 — 应用目录安装（核心）

**改动面（预期）**：

- `STORE_ENTRY` / `STORE_INSTALLED` 扩字段（或旁路结构，避免一次胀爆）。  
- PKG 解析：不止 `depends=`。  
- `StoreInstall`（app 分支）：`MakePath(Apps/<id>)` → 拷 ELF、PKG.TXT、`Assets/` 树。  
- DB：`si` 约定 + 可选 `sx`/`sy`。  
- 样包：`guidemo` 或新建 `mygame` 带 `Assets/icon.bmp`。  
- 兼容：扁平旧 app 检测逻辑。

**验收**：

- `store install <appid>` 后存在 `Apps/<id>/<file>.ELF` 与 `Apps/<id>/PKG.TXT`。  
- Shell `exec` 新路径可跑。  
- 旧扁平包仍可装/卸（回归）。  
- smoke-boot PASS。

**不要**：改 Desktop；改 ToyGfx；删树 API 若未就绪则先做序 0。

### 第 2 步 — 系统字体共享（方案 C）

**改动面（预期）**：

- 应用开发文档：`ToyGfxInitialize` / 文本绘制不写字体路径。  
- 可选：`ToyGfx` 内注释或空实现钩子。  
- **不做**完完整私有字体栈，除非本步范围写明。

**验收**：无字体路径的示例 app 能显示系统字；`Assets/Fonts` 仍唯一系统字库根。

### 第 3 步 — 桌面 / 开始菜单动态生成

**改动面（预期）**：

- `DesktopLoadAppIcons`：扫已装 app 且 `desktop=yes`，图标路径 `Apps/<id>/<icon>`。  
- `RebuildStartMenu`：固定项 + 动态 `taskbar=yes`。  
- 固定系统图标表保留。

**验收**：装带 `desktop=yes` 的样包后桌面出现图标；卸前须能点开；无 Store 字段的旧包行为可定义（不上桌面 / 仅菜单按 ELF 发现——须写死一种）。

### 第 4 步 — 卸载

**改动面（预期）**：

- app：`RemoveTree(Apps/<id>)` + 清 `si`/`sd`/`sx`/`sy`。  
- 先/后通知 Desktop 摘图标与菜单项（或 Reload 扫描）。  
- font/asset：保持现扁平删除。

**验收**：卸后无残留目录与 DB 键；菜单/桌面无死链；依赖拒绝规则不回归。
