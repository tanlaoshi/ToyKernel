## 二、现有启动怎么接串口

`smoke-boot.sh` 清掉已有 QEMU，再跑：

```bash
run-split.sh --kill-qemu --headless
```

标准输出进日志，每秒看一次 `ToyOS ready` 或 `ToyOS 就绪`。看到就退出 0。它不往里送命令。

`--headless` 只加 `-display none`。串口仍是 `-serial stdio`。VGA 还在，所以进的是桌面里的 `ShellTask`，不是纯串口壳。`ShellTask` 会读 COM1：

1. 第一个回车调用 `GuiOpenShell()`，这一下不当成命令。
2. 串口出现 `toyos>`。
3. 之后的可打印字符进入命令行，`\r` 执行。

本机目前没有 `expect`。第 1 步开跑前要先 `sudo apt install expect`。

> **更新（2026-09-24）**：expect 已装（`/usr/bin/expect` 5.45.4）。`test-shell.sh` 已用 LF 行尾落地，`./test-shell.sh` 直接可跑，五条命令全过，`exit 0`。

## 三、第 1 步：`test-shell.sh`

`expect` 拉起 `run-split.sh --kill-qemu --headless`。断言只看这条命令之后、下一次 `toyos>` 之前的新输出。启动日志里已有 `TOYOS` 和 `[Mod] Scheduler`，不能对整段日志检索。

### 超时

| 等待 | 超时 | 失败处理 |
| ---- | ---- | -------- |
| 启动到 `ToyOS ready` | 90s | 打印日志尾部，exit 1 |
| `\r` 后到 `toyos>` | 10s | 打印日志尾部，exit 1 |
| 命令后到下一个 `toyos>` | 15s | 打印日志尾部，exit 1 |
| `halt` 后 QEMU 退出 | 10s | 强制 kill，exit 1 |

### 日志

```tcl
set LOG "/tmp/toyos-test-shell.log"
log_file $LOG
```

失败时打印日志尾部：

```tcl
proc fail_dump { } {
    send_user "=== FAIL, log tail ===\n"
    catch { exec tail -80 $LOG }
    exit 1
}
```

### 清理

脚本结束时杀掉 QEMU，并注册退出钩子：

```tcl
proc cleanup { } {
    catch { exec pkill -f "qemu-system-x86_64" }
}
```

开跑同样会先杀掉本机上已有的 `qemu-system-x86_64`。

### 断言

| 命令 | 断言 |
| ---- | ---- |
| `help` | `commands:` |
| `ls` | `TOYOS.DB` |
| `lsdev` | `Bound Drivers` |
| `show memory` | `physical memory` |
| `list tasks` | `pid=` |

### 结束

1. 五条命令都通过。
2. 发送 `halt`。
3. 等 QEMU 退出，最多 10 秒。
4. 未退出则 kill（实测：`halt` 调 `HalCpuPark()`，QEMU 进程不退出，必走此步）。
5. `exit 0`（kill 后仍算 PASS）。

### 失败

1. 打印日志尾部。
2. kill QEMU。
3. `exit 1`。

## 五、内核 bug 清单

第 2 步 `test-user.sh` 在 QEMU 跑用户程序时暴露并修复了 4 个内核 bug（均未 TG）。第 1 步 `test-shell.sh` 不触发（只跑 Shell 内建命令）。

| # | bug | 现象 | 修复 | 文件 |
| - | --- | ---- | ---- | ---- |
| 1 | 串口输出无锁 | fork 后父子并发 printf 字节交错（PIPEDEMO `root=0x000PING000...`） | `HalSerialWriteChannel` 加 `SPIN_LOCK gSerialLock`（关中断，每次调用原子） | `HAL/X64/Hal/HalSerial/HalSerialWrite.c` |
| 2 | exec banner 与子进程输出交错 | `ProcessStartElf` 先 `SchedulerCreateUser` 后打 "process: started"，新任务中途抢占致 `process: started FORK.C`/`ELF` 拆行 | banner 移到 `SchedulerCreateUser` 之前 | `Core/Process/ProcessLoad.c` |
| 3 | fd 0/1/2 未预留 | `TaskClearFds` 清空所有 fd，`pipe()` 分到 `Pfd[1]=1`，子进程 `write(1)` 命中 `SysWrite` 的 `Fd==1\|\|2` 走 console，PIPEDEMO 读空 | `TaskClearFds` 预留 fd 0/1/2 为 `FD_KIND_CONSOLE` 占位；`SysFstat` 拒绝该 Kind | `Core/TaskFd/TaskFd.c`、`Include/Scheduler.h`、`Core/Syscall/SyscallFs.c` |
| 4 | 文件映射读 `Data` 缓冲 | `ProcessMmap` 要求 `Fds[Fd].Data` 非零且从 `Data[off]` 读，但流式文件 `Data=0`，文件映射永远失败（MMAPDEMO `file mmap fail`） | 去掉 `!Data` 检查；改用 `VfsServiceReadFileAt(Path, off, Page, ...)` 按偏移读 | `Core/Process/ProcessMem.c` |
| 5 | signal 接受非法 handler | `SchedulerSignal` 对 `signal(SIGTERM,(sighandler_t)2)` 返回成功（Old），LIBCDEMO 期望 SIG_ERR | 自定义 handler（>IGN）须 ≥ `USER_CODE_VIRT`，否则返回 SIG_ERR | `Core/Scheduler/SchedulerUser.c` |

**约束**：三架构可编；不改用户 API；新代码 ≤300。修复后 `test-shell.sh`（5/5）与 `test-user.sh`（7/7）均 PASS，无回归。
