# 人民可读代码（普通人也能看懂 ToyOS）

> **状态**：规格活文档（2026-10-05）。路线图文首 ★ 仍空；开刀认 [`进展-2026-10.md`](进展-2026-10.md)。  
> **写给**：愿意打开源文件、但不是内核老手的人。  
> **一句话**：标识符继续用见字知意的英文；文件头和难懂处用**人话中文**讲清「这是干什么、为什么、从哪读」。  
> **本柱不做**：拼音函数名、每行注释、一次翻全库、改 ABI / 行为。

---

## 0. 为什么要立这一柱

此前代码写得很紧：分层清楚、PascalCase、单文件 ≤300。对长期写内核的人友好，对普通人仍像密电——文件头尽是 PR 号，块注释只写给下一个 Agent，打开 `.c` 不知道该从哪一行开始读。

「人民的操作系统」先要求：**一个肯花十分钟的人，能读完一个样板文件，说出它在干什么。**  
不是要求每个人都能改分页；是要求「任务管理器 / 桌面入口 / 学生调度器」这类入口，读起来像说明书，而不是考古。

已有家底（本柱站在上面，不另起炉灶）：

| 已有 | 本柱补什么 |
| ---- | ---------- |
| [`开发命名规范.md`](../开发/开发命名规范.md) 全词、禁止瞎缩写 | 规范管**名字**；本柱管**怎么讲给人听** |
| [`如何写一个*.md`](../开发/如何写一个调度器.md) 学生短文 | 短文指向文件；文件头要能**单独**读懂 |
| 许多文件已有中文头（如 `Desktop.c`、`TaskMgr.c`） | 统一成同一套「人话头」；去掉只对作者有用的暗号 |
| 坏味道 P0（魔法数字 / 吞返回值） | 可读 ≠ 清坏味道；两柱勿混刀 |

## 1. 钉死：改什么、不改什么

### 1.1 改（每刀允许）

| 项 | 说明 |
| -- | ---- |
| **人话文件头** | 每个被点名的 `.c` / 公开 `.h` 顶部换成 §2 模板 |
| **「为什么」注释** | 只给：非显然的约束、历史坑、与别的文件的约定 |
| **局部名更直白** | 仅文件内 `static` / 局部变量；公开 API **不动** |
| **指向已有短文** | 头里写「想照着做 → `Documents/开发/如何写….md`」 |

### 1.2 不改（红线）

| 禁止 | 理由 |
| ---- | ---- |
| 函数 / 类型 / syscall **改成拼音或中文标识符** | 破坏命名规范、grep、三架构、开课 ABI |
| POSIX / CRT 名（`fopen` / `malloc`） | 课堂要认这些名字 |
| 改控制流、结构体布局、返回值语义 | 可读刀 = **零行为** |
| 每行复述代码（`i++` 旁写「i 加一」） | 噪音，比不注释更糟 |
| 一次改一整层（整个 `CodeD-Services/`） | 一刀一模块；diff 必须能审 |
| 把 PR 号当唯一说明 | 号可留在进展里；文件头要说人话 |

### 1.3 和命名规范怎么分工

- **给机器 / grep / 链接器看的**：仍 PascalCase 英文全词（`ToyUiSetLabel`，不是 `SheZhiBiaoQian`）。  
- **给人扫一眼的**：中文头 + 少量「为什么」。  
- 普通人路线：**先读文件头（中文）→ 再对名字（英文）→ 再跟函数走。**

## 2. 人话文件头（强制模板）

被本柱改到的文件，文件头按下面四块写（可短，不可缺「这文件」和「从哪读」）：

```c
/*
 * 人话：这里是「任务管理器」窗口程序。开机后在开始菜单里点它，
 *       或在 Shell 里 exec TASKMGR.ELF。它列出内核里正在跑的任务。
 *
 * 从哪读：main（文件末尾）→ Refresh 拉一张快照 → Paint 画当前这一行。
 *
 * 别改：toy_task_snap / TOY_TASK_SNAP 的字段含义（与 Shell 命令 ps 同一份）。
 *       按钮编号 0/1/2 与 ToyUiAddButton 的添加顺序绑死。
 *
 * 想照着做：Documents/开发/如何写一个任务管理器App.md
 */
```

| 块 | 写什么 | 不要写什么 |
| -- | ------ | ---------- |
| **人话** | 这个文件在用户眼里是什么；一句话场景 | `PR-S3-xxx`、内部票号 |
| **从哪读** | 建议的阅读顺序（2～4 个函数名） | 「详见 Git 历史」 |
| **别改** | 和别人的契约（ABI、顺序、锁） | 空泛的「小心修改」 |
| **想照着做** | 已有短文路径；没有就写「暂无，本柱不新写长文」 | 把整篇教程贴进注释 |

公开头文件（`Include/`、`User/include/`）同样四块，但「从哪读」改成「先看哪个函数 / 哪张表」。

## 3. 块注释：只解释「为什么」

**要写：**

```c
    /* 内核画客户区文字时认 '\\n' 换行；一行太长会被裁掉，所以拆成两行。 */
```

**不要写：**

```c
    /* 调用 snprintf */
    snprintf(Line, sizeof(Line), ...);
```

存量里「PR-G-desk-1：图标拖放」这类可以改成「图标位置松手后写入 TOYOS.DB，下次开机读回来」——**行为说明留下，刀号请走进展文**。

## 4. 刀表（实现）

> 一刀一事；**零行为**；新/改注释不破 ABI。涉及桌面观感的刀仍 `smoke-boot`（行为不该变，作回归）。  
> **JX 只认进展文首 ★**；本表是选型，不自动开刀。

| 刀 | 范围 | 一句话 | 预估 | 破 ABI |
| -- | ---- | ------ | ---- | ------ |
| **PR-READ-0** | 本文 | 钉模板与红线 | 文档 | 否 |
| **PR-READ-1** | `CodeE-User/Apps/TaskMgr.c` | 用户态样板：头四块 + 去暗号注释 | ≤80 | 否 |
| **PR-READ-name** | `KernelTask` 演示槽名 | `ktdemo` → `KernelTaskDemo` | ≤40 | 否 |
| **PR-READ-2** | 学生调度器 `SchedulerPriority.c` + 必要时补一行指向短文 | 课堂可替换模块样板 | ≤80 | 否 |
| **PR-READ-3** | `Desktop.c`（仅核心文件头与入口函数旁） | 普通人看见的桌面从哪进 | ≤80 | 否 |
| 随后 | 点名再排：Shell 入口、`如何写一个分配器/文件系统` 对应实现 | 一模块一刀 | — | 否 |

**验收（每刀）：**

1. 找一个没改过内核的人（或自己装外行）：只读文件头，能说出「这文件干什么、该从哪函数读」。  
2. `./build.sh`（该文件若在 Common/Include/User：抽验 `arm64` 或 `riscv` 至少一次——本柱几乎只动注释，仍守三架构原则）。  
3. 用户态样板：`exec TASKMGR.ELF` 行为与改前相同（READ-1）。  
4. **不用**为「多了几行中文注释」改 ABI 冻结文。

**手测：** READ-0 不用。READ-1 起：若只改注释、构建通过 → 回复写「建议扫一眼 TaskMgr 仍能开窗；非强制」。动到绘制/事件则要手测。
