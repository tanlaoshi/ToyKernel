## 一、目标与硬约束

### 目标

1. **名称**：Vendor/Device/Class → 可读字符串（内置表，无外部 DB）。  
2. **状态**：至少区分 unbound / bound（与现网「谁在驱动」对齐）。  
3. **资源展示**：BAR **基址**；若阶段 4 已合入则附带 **Size** / IRQ 详表（本柱不负责探测）。  
4. **观察面**：Shell `lsdev` + GUI DevicesUi **同源字段**，默认可读、`-v` 详表。

### 硬约束

| # | 约束 |
| - | ---- |
| 1 | **扩展** `Device.h`（加字段/枚举）；**不**改现有 API **签名**与语义 |
| 2 | **不改**现有驱动 Probe/行为（仍可自扫 PCI） |
| 3 | 新 `.c` ≤300；`PCIe.c` 已 ~316 → **勿**再塞 BAR 探测（归阶段 4） |
| 4 | **分步**；每步可 build + smoke；确认后再开第 1 步 |
| 5 | Core **不** include `HAL/*/PCIe.h`（名称表放 `Common/Library/`，枚举仍在 HAL） |
| 6 | **不**引入 pci.ids 外部文件；内置常见项即可课堂用 |
| 7 | **不**占文首 ★，除非明文改 ★ |

### 明确不做（本柱）

- ❌ 完整 pci.ids / 在线更新  
- ❌ 在 UI/lsdev 里 Bind/Unbind 改驱动（观察面）  
- ❌ 强制所有驱动改走 `DeviceBindDriver`（可另柱）  
- ❌ 一次做完 4 步

## 二、现状锚点（分析 · 2026-09-22）

> 答任务书「先分析」；路径以仓库为准。

### 2.1 `Include/Device.h`

| 项 | 现状 |
| -- | ---- |
| `Name[32]` | 短类名：`ahci` / `xhci` / `net` / `pci`…（枚举时填） |
| 匹配 | `Vendor` / `Device` / `Compatible[64]` |
| PCI 位 | `PciBus` / `PciDev` / `PciFn` |
| 资源 | `Bar[6]`（**仅基址**）、`Irq` |
| 绑定 | `Driver` / `Instance` / `Bound` |
| **无** | `FriendlyName`、`Class`/`Subclass`/`ProgIf`、`DEVICE_STATE`（`BarSize[]` 见阶段 4，本柱不首加） |

API：`DeviceAdd` / `Get` / `Find*` / `BindDriver` / `Unbind` / `ListDump` / `EnumerateAll`。

### 2.2 `Core/Device.c`

- 表：`gDevices[128]`。  
- `DeviceEnumerateAll` → `HalDeviceEnumerate()`。  
- **`DeviceBindDriver` / `Unbind` 已实现但全树无调用方** → 表内 `Bound` 几乎恒为 0。  
- 真正「已绑定」观感来自 **`ToyDriverInstance*`**（`lsdev` 下半段 Bound Drivers）。

### 2.3 `HAL/X64/DeviceEnum.c`

- 扫全 PCI 功能；只读配置（**不**写 Command，与 USB 专用扫描区分）。  
- 读 Class/Subclass/ProgIf **仅**喂给本地 `PciClassName` → 写入 `Name[32]`，**不入库**。  
- `FillBars`：基址；**无 size**。

### 2.4 `lsdev`

- 文件：`Common/Services/ShellCommands/ShellCommandsSystem.c` → `CommandLsdev`。  
- 正统名：`list devices`；别名 `lsdev`。  
- 输出：`DeviceListDump()`（`Core/DeviceDump.c`）+ Bound Drivers 段。  
- 设备行形态：`[bb:dd.f] vvvv:dddd  <Name>  <Driver|(unbound)>` — **无**友好名、无 BAR 大小、无 `-v`/`-c` 过滤。

### 2.5 `PCIe.c`

- 有 `PciReadConfig` / `PciWriteConfig`。  
- **无** `PciBarSize`；文件已 **>300 行** → **归阶段 4** `PCIeBar.c`，本柱不建。

### 2.6 DevicesUi

- 列表/详情：PCI 位 + `vvvv:dddd` + `Name` + 驱动名 + BAR 基址 hex。  
- 过滤 All/Bound/Free 看 `Dev->Bound`（与表未真正 Bind **脱节**）。  
- `DevicesUiPaint.c` ~258 行，近上限 → 详表逻辑优先进 Model 或小辅助文件。

### 2.7 名称表

- **无** `PciNames`；仅 `DeviceEnum.c` 内短 `PciClassName`；E1000 有芯片小表。

## 三、Agent / 设计思考（纳入规格）

### 3.1 `Name` vs `FriendlyName`

- 保留 `Name[32]` 作**短类/键**（兼容现 lsdev/UI）。  
- 新增 `FriendlyName[64]`（或 48）作人类标题，例如 `Intel xHCI Controller`。  
- 缺表项：回退 `PciGetClassName` → 再回退现 `Name`。

### 3.2 「Bound」语义（关键）

任务书 `DEVICE_STATE_BOUND` 若只抄 `Dev->Bound`，课上几乎全是 unbound。

**推荐（实现时写死一种）**：

| 策略 | 做法 |
| ---- | ---- |
| **A（推荐）** | `State`/`显示 bound`：若存在 `ToyDriverInstance` 认领同 `PciBus/Dev/Fn`（或驱动名匹配），视为 bound；可选同步写回 `Dev->Bound`/`Driver` **只读填充**（不改驱动 Probe） |
| **B** | 仅显示表字段；另开柱真正接线 `DeviceBindDriver` |

本柱默认 **A**：观察面正确，驱动行为不变。

### 3.3 Class 是否入库

- **入库** `Class/Subclass/ProgIf`：过滤 `-c`、UI、避免重复读配置。  
- 枚举时已读到，成本为零。

### 3.4 BAR 大小探测

**已移交阶段 4**（见 [`设备管理器资源管理.md`](设备管理器资源管理.md)）。本柱若先落地，`-v`/UI 在 `BarSize` 未合入时只打基址。

### 3.5 名称表设计

```text
Common/Library/PciNames.c     # ≤300；表可再拆 PciNamesData.c
Include/PciNames.h            # 公共；DeviceEnum / DeviceDump / Shell 可用
```

| 表 | 内容 |
| -- | ---- |
| Vendor | 常见 VID → 短名（Intel/AMD/Virtio/Red Hat…） |
| Device | `(VID,DID)` → 友好名（覆盖课堂：xHCI、AHCI、NVMe、e1000/e1000e/i219、virtio-net/blk、QEMU VGA…） |
| Class | Class/Subclass[/ProgIf] → 类名（可迁出现有 `PciClassName`） |

查找：线性表即可（设备数课堂级）；超 300 行则 Data 与 Lookup 拆文件。

### 3.6 lsdev 改进与兼容

- 默认：一行可读（位 + FriendlyName + state/driver）。  
- `-v`：VID:DID、class、BAR0+size、IRQ。  
- `-b` / `-u` / `-c <class>`：过滤。  
- **保持** `list devices` 别名；旧脚本不依赖 hex 行格式则无妨；若有课义依赖旧行，文档注明变更。

### 3.7 DevicesUi 同步

- 第 4 步后或紧随小刀：详情显示 FriendlyName（+ `BarSize` 若阶段 4 已合入）；Bound 过滤走策略 A。  
- **勿**第 1 步就大改 UI；**勿**本柱做左栏 About（见系统摘要柱）。

### 3.8 与已归档 DEV 柱

- 本柱 = **增强观察面**，不是推翻 Device 框架。  
- 收官后归档指针挂 §七，细则可留在本文或迁 `已完/`。

## 四、PR 拆分（4 步）

| 序 | PR（建议名） | 交付 | 验收 |
| -- | ------------ | ---- | ---- |
| **1** | **PR-DEV-names** | `PciNames.h` / `PciNames.c`（+ 可选 Data）；Vendor/Device/Class 查询 | 单测或 Shell 临时打印；smoke；表覆盖 QEMU virtio + e1000 + xHCI |
| **2** | **PR-DEV-node** | `DEVICE_NODE` 扩 FriendlyName / Class* / State（**不含** `BarSize`，归阶段 4） | 结构体布局兼容；旧调用方零改或仅清零新字段 |
| **3** | **PR-DEV-enum** | `DeviceEnum` 填 Class* / FriendlyName（**不**调 `PciBarSize`） | QEMU 可见新字段；不写 Command |
| **4** | **PR-DEV-lsdev** | `CommandLsdev` + `DeviceDump` 可读输出与 `-v/-b/-u/-c`；有 `BarSize` 则展示 | 课上手读；DevicesUi 可同刀或 +0.5 刀对齐 |

**依赖**：1 → 2 → 3 → 4。  
**可停**：1 单独也有教学价值（表可给驱动课用）。

### 第 1 步细节（名称库）

- API（名可微调，须 PascalCase）：  
  `PciGetVendorName` / `PciGetDeviceName` / `PciGetClassName`。  
- 未命中返回 `NULL` 或 `""`（实现时统一，调用方回退）。  
- **不要**在本步改 `DEVICE_NODE` / lsdev。

### 第 2 步细节（结构扩展）

```c
typedef enum {
    DEVICE_STATE_UNBOUND = 0,
    DEVICE_STATE_BOUND,
    DEVICE_STATE_DISABLED, /* 预留 */
    DEVICE_STATE_ERROR     /* 预留 */
} DEVICE_STATE;
```

新增建议字段：`FriendlyName[64]`、`Class`、`Subclass`、`ProgIf`、`State`。  
**不要**在本步加 `BarSize` / `IrqMode`（阶段 4）。  
`DeviceInitialize`/`Add`：新字段清零；若 `FriendlyName[0]==0` 且 PCI，用 `PciGetDeviceName` 填充。

### 第 3 步细节（HAL 填充）

- `HalDeviceEnumerate`：写入 Class*、FriendlyName。  
- `State`：本步可仍 UNBOUND；或按策略 A 扫一遍 Instance（若 Instant 表可从公共头看见）。  
- **禁止**枚举路径写 PCI Command；**禁止**本步做 BAR size 探测。

### 第 4 步细节（lsdev）

- 解析 `-v`/`-b`/`-u`/`-c`；文末设备计数（Total/Bound；段名避免与 GUI「摘要」混淆）。  
- `PrintDevice` 可放 `DeviceDump.c` 或 `ShellCommandsSystem` 旁新辅助文件（控 300 行）。  
- 同步改 DevicesUi 展示 FriendlyName（推荐同刀或立即下刀）；**GUI About 左栏**见独立柱，勿揉入本步。
