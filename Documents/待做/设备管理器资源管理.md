## 一、目标与硬约束

2. 记录 **IrqMode**（INTx / MSI / MSI-X）；保留已有 Interrupt Line。  
3. 提供 MMIO 区间登记与**重叠检测**；QEMU 默认拓扑期望无冲突。

## 三、设计

### 3.1 `DEVICE_NODE` 扩展

```c
/* 资源（在现有 Bar[6] / Irq 旁扩展） */
UINT64 BarSize[6];
UINT8  IrqMode;   /* 0=INTx, 1=MSI, 2=MSI-X */
```

- `DeviceAdd` / `ZeroNode`：清零并拷贝。  
- **不**改现有字段布局语义；仅尾部或资源区追加（实现时注意对齐，课堂无 ABI 冻结要求）。

### 3.2 BAR 大小探测

标准 PCI：对 BAR 槽写 `0xFFFFFFFF`，读回掩码算 size，**必须写回原值**。

| 类型 | 判定 | Size 公式（任务书） |
| ---- | ---- | ------------------- |
| 空槽 | Mask==0 | 0 |
| IO | `Mask & 1` | `(~(Mask & 0xFFFFFFFC)) + 1` |
| MMIO 32 | 否则 | `(~(Mask & 0xFFFFFFF0)) + 1` |

**相对任务书补强（必须）**：

1. **64-bit MMIO**：与现 `FillBars` 对齐——对 low（及需要时 high）探测；**高槽 `BarSize` 置 0**，避免双重登记。  
2. 仅对「有意义」的槽探测（可与非零基址或 type 位对齐）；探测失败/异常则该槽 Size=0。  
3. 时机：枚举阶段、驱动 Probe **之前**；短暂写配置空间，QEMU 先验。

```text
HAL/X64/PCIeBar.c     # PciBarSize(...)；≤300
DeviceEnum.c          # 填 Node.BarSize[b]；调用旁路，不胀爆本文件
```

### 3.3 IRQ / IrqMode

| 来源 | 字段 | 说明 |
| ---- | ---- | ---- |
| 配置 `0x3C` 低字节 | `Irq`（已有） | Interrupt Line；MSI 启用后仍可能残留 |
| Cap `0x11` | `IrqMode = 0x02` | MSI-X **能力存在**（非「已 Enable」） |
| 否则 Cap `0x05` | `IrqMode = 0x01` | MSI |
| 否则 | `IrqMode = 0x00` | INTx（或无 Pin） |

优先级与现 `PciEnableMsi` 一致：**先 MSI-X，再 MSI，再 INTx**。  
本柱只**记录能力**，**不**调用 `PciEnableMsi`、不改中断路由。

`PciFindCap`：去掉 `static`，在 `PCIe.h` 声明：

```c
int PciFindCap(UINT8 Bus, UINT8 Device, UINT8 Function, UINT8 Id);
```

### 3.4 MMIO 冲突检测

```c
typedef struct {
    UINT64 Base;
    UINT64 Size;
    DEVICE_NODE *Owner;
} RESOURCE_REGION;

int DeviceRegisterMmio(DEVICE_NODE *Dev, UINT64 Base, UINT64 Size);
```

- 静态表（如 `gMmioRegions[64]`）；满则返回错误。  
- 重叠：`Base < Other.Base + Other.Size && Base + Size > Other.Base`（半开区间习惯写清）。  
- `Size==0` 或 `Base==0`（实现时约定是否跳过 0 基址）→ 不登记。  
- 冲突日志用 `Dev->Name`（无 FriendlyName 时）；勿依赖阶段 1。

**策略 A 调用点**（推荐写在 `DeviceEnumerateAll` 末尾或 HAL 枚举扫完后的 Core 钩子）：

```text
for each Dev in DeviceGet(*):
  for b in 0..5:
    if BarSize[b]==0: continue
    if BAR 为 IO（需保留 type 信息或约定：仅登记 MMIO）: continue
    DeviceRegisterMmio(Dev, Bar[b], BarSize[b])
```

IO vs MMIO：枚举时若未存 type 位，可 (a) 探测时记下 `BarIsIo[6]`，或 (b) 约定「仅当 `BarSize` 来自 MMIO 探测路径才登记」。推荐 **(a) 最小**：在 `PciBarSize` 旁提供 `PciBarIsIo` 或枚举循环内用读回 Mask bit0 判断，**不必**入库新数组若局部可得。

### 3.5 观察面（第 2 刀最小）

- `lsdev -v`（及 `list devices -v`）：在现有行下或同行追加 `irq=N mode=intx|msi|msix`。  
- 无 `-v` 时行为与今相同（或仅多 IRQ 数字——实现选**兼容默认**，详表走 `-v`）。  
- DevicesUi：**本柱不强制**；可另刀。

### 3.6 与驱动 / Core 边界

| 层 | 职责 |
| -- | ---- |
| HAL `PCIeBar` / `DeviceEnum` | 读配置、算 Size、填 IrqMode |
| Core `DeviceResource` | 区间表与冲突算法（平台无关） |
| 驱动 | **本柱不改**；日后可选主动 `DeviceRegisterMmio` 登记非 BAR 窗口 |

## 四、PR 拆分（3 刀）

| 序 | PR（建议名） | 交付 | 验收 |
| -- | ------------ | ---- | ---- |
| **1** | **PR-DEV-bar-size** | `BarSize[6]`；`PCIeBar.c`/`PciBarSize`；`DeviceEnum` 填充；`DeviceAdd` 拷贝 | 编译通过；QEMU 上典型设备 Size≠0（如 xHCI/AHCI BAR）；写回后设备仍可后续 Probe |
| **2** | **PR-DEV-irq-mode** | `IrqMode`；导出 `PciFindCap`；枚举填充；`lsdev -v` 显示 IRQ + mode | 编译通过；`-v` 可见；驱动行为不变 |
| **3** | **PR-DEV-mmio-conflict** | `Core/DeviceResource.c` + `DeviceRegisterMmio`；枚举后策略 A 登记 | 冲突检测实现；QEMU 无冲突日志；编译通过 |

**依赖**：1 → 2 → 3（第 3 刀依赖 Size；第 2 刀与 Size 弱耦合但串行更清晰）。

### 第 1 刀细节

- `Device.h` 加 `BarSize[6]`。  
- `UINT64 PciBarSize(UINT8 Bus, UINT8 Dev, UINT8 Func, int Bar)`。  
- 64-bit：与 `FillBars` 同序推进索引；高 dword 槽 Size=0。  
- **禁止**枚举路径写 PCI Command。

### 第 2 刀细节

- `Device.h` 加 `IrqMode`。  
- `PciFindCap` 导出；枚举：`0x11` → `0x02`，`0x05` → `0x01`，否则 `0x00`。  
- `DeviceDump` / `CommandLsdev`：解析 `-v`；打印 `Irq` + `IrqMode`。  
- **不**改中断使能。

### 第 3 刀细节

- `Core/DeviceResource.c` ≤300；声明进 `Device.h`。  
- Makefile / 构建脚本纳入新 `.c`。  
- 策略 A 自动登记；冲突仅 Debug 日志。  
- 可选：Shell 调试命令**不做**（控范围）。
