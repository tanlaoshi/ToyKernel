## 三、阶段 1 · 调度器（分析）

### 3.1 现有 `Scheduler` 结构

调度器已按文件拆开（约 1.8k 行），**尚无** Ops 表：

| 文件 | ~行 | 职责 |
| ---- | --: | ---- |
| `Core/Scheduler/Scheduler.c` | 291 | Init / Create / 优先级·亲和 / `ActivateTask` |
| `Core/Scheduler/SchedulerRunq.c` | 258 | **就绪队列、入队排序、偷任务、`PickNext`/`PickHomeCpu`** |
| `Core/Scheduler/SchedulerSignal.c` | 261 | `SchedulerOnTimer` → `PickNext` |
| `Core/Scheduler/SchedulerUser.c` | 285 | fork / yield / kill |
| `Core/Scheduler/SchedulerWait.c` | 293 | wait / zombie / exit |
| `Core/Scheduler/SchedulerSleep.c` | 90 | sleep 唤醒 |
| `Core/Scheduler/SchedulerBoot.c` | 193 | idle / `SchedulerStart` / 钉核 |
| `Include/Scheduler.h` | 134 | 对外 ABI |
| `Include/SchedulerPrivate.h` | 54 | 内部：`gTasks`、runq 符号、锁 |

对外入口在 `Scheduler.h`（Create、OnTimer、Yield、Sleep、Wait、Fork…）。**没有**名为 `Schedule` 的函数；真正「调度决策」是 `PickNext`（由 `SchedulerOnTimer` / `SchedulerYield` 调用）。

**政策（可替换）** vs **框架（应保留）**：

| 政策（候选 Ops） | 框架（不动语义） |
| ---------------- | ---------------- |
| 入队次序（优先级 + 同优 FIFO） | `TASK` / `gTasks` 槽位分配 |
| `PickNext` / `PickHomeCpu` / steal | Create / fork / wait / signal / sleep |
| （将来）时间片 / `ShouldPreempt` | `ActivateTask`、页表、syscall、HAL 定时器 |
| | SMP 锁约定、`SchedulerStart` 钉核 |

### 3.2 现有 `TASK` 结构

定义在 `Include/Scheduler.h`。与调度相关字段：

- `State`：`UNUSED` / `READY` / `RUNNING` / `BLOCKED` / `ZOMBIE`
- `Priority`、`Affinity` / `HomeCpu` / `OnCpu`、`InRunQueue`
- `Ticks`：计数，**不是**时间片
- **无** `next`/`prev`：就绪队列是每核 `TASK *Slot[]` 数组

`Process.h` 是 exec/brk 等 API，**不是**进程实体；可调度实体就是 `TASK`。

政策代码只应碰 State / Priority / 亲和 / InRunQueue。学生模块**不宜**直接 `#include SchedulerPrivate.h`（含 `gTasks`、锁）；应提供更薄的 Policy 辅助，或把锁留在框架侧。

### 3.3 现有 Makefile / 构建

- 真构建在 `Makefile`；`build.sh` 为包装。
- 源文件靠 **wildcard**：`CORE_SRCS += $(wildcard Core/Scheduler/*.c)`。
- 已有旋钮：`ARCH` / `BOARD` / `LWIP` / `TOY_DEMO_DRIVER`——**没有** `SCHEDULER=`。
- **没有** `Common/Modules/`、`Tests/`、`runtests`。

**推论**：学生 `.c` **不能**放进 `Core/Scheduler/`（会被默认链进 Kernel）。须用 `SCHEDULER=` **显式**拉取 `Common/Modules/...`。

### 3.4 现有可替换先例

| 模式 | 位置 | 选择方式 |
| ---- | ---- | -------- |
| `FS_OPS` | `Include/Vfs.h` | `VfsRegister` / `VfsSelect` |
| `BLOCK_BACKEND` | `Include/Block.h` | `BlockRegisterBackend` / Attach |
| `NET_BACKEND` / `INPUT_BACKEND` | Driver* | `ToyDriver*Attach` |
| `WINDOW_OPS` 等 | `Include/CoreOps.h` | Register |

调度器阶段 1 采用：**编译期选实现 + `SchedulerOpsRegister`**（形似 FS_OPS，但默认由 Make 决定链哪个 `.c`）。

### 3.5 打算如何抽接口

相对「框架放 `Common/Library/Scheduler.c`」的微调（贴现有分层）：

```
Include/SchedulerOps.h              # 新：SCHEDULER_OPS
Include/Scheduler.h                 # 对外 API 不动
Core/Scheduler/*.c                  # 框架保留（Create/Timer/Wait…）
Core/Scheduler/SchedulerOps.c       # 薄胶水：Register + 默认转发（≤50 行）
Common/Modules/SchedulerRoundRobin/SchedulerRoundRobin.c
                                    # 现 SchedulerRunq.c 政策迁入
```

**不建议**把框架整体搬到 `Common/Library/`（会与 Core/Syscall/Process 分层打架）。

`SCHEDULER_OPS` 最小集合：

```c
typedef struct {
    void   (*Init)(void);
    void   (*Enqueue)(UINT32 Cpu, TASK *T);
    void   (*Remove)(TASK *T);
    UINT32 (*PickHome)(const TASK *T);
    TASK  *(*PickNext)(UINT32 Cpu);
    /* 可选后续：int (*ShouldPreempt)(TASK *Cur); */
} SCHEDULER_OPS;

void SchedulerOpsRegister(const SCHEDULER_OPS *Ops);
const SCHEDULER_OPS *SchedulerOpsGet(void);
const SCHEDULER_OPS *SchedulerRoundRobinOps(void);
```

落地要点：

1. `SchedulerInitialize` 内 `SchedulerOpsRegister(SchedulerRoundRobinOps())`。
2. `OnTimer` / `Yield` 调 `Ops->PickNext`，不再直调本地 `PickNext`。
3. Makefile：`SCHEDULER ?= round-robin` → 只链对应 Modules 目录；**不** wildcard 扫学生树。
4. 默认行为 = 今日 Runq（优先级 + 同优 FIFO + steal）。
5. 锁优先留在框架；模块只做排序/挑选，避免学生死锁。

### 3.6 打算如何实现测试

现状：**零测试骨架**，需新建。

| 层 | 做什么 |
| -- | ------ |
| **Host 单测（首选）** | `Tests/TestScheduler.c` + stub（锁 / `HalCpuCount` / idle），只链所选 `SCHEDULER` 模块；测入队次序、同优 FIFO、亲和、空队列→idle |
| **`runtests scheduler`** | 新 `Scripts/runtests.sh` 或 Make 目标，链 `Build/Tests/TestScheduler`，失败非 0 |
| **默认 Kernel** | 永不链学生树；仅 `SCHEDULER=student`（或指定目录）时链入 |
| **QEMU smoke** | 回归用，不替代政策评分 |

验收：

| 命令 | 期望 |
| ---- | ---- |
| `make SCHEDULER=round-robin`（或默认） | 与现网行为一致 |
| `runtests scheduler` | 对 RR Ops 断言通过 |
