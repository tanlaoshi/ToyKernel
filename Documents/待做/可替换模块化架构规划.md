## 一、目标与硬约束

### 目标

1. **接口与实现分离**：接口在 `Include/`（稳定）；可替换实现在 `Common/Modules/`。
2. **编译时选择**：Makefile 变量选实现（如 `SCHEDULER=round-robin`、`MEMORY=bitmap`）。
3. **统一测试**：同一套测试验证默认实现与学生实现。

### 硬约束

| # | 约束 |
| - | ---- |
| 1 | **不改**对外现有 API（`SchedulerCreate` / `PhysicalMemoryAllocatePages` 等签名不变） |
| 2 | 默认实现行为与现网一致 |
| 3 | 每刀独立可编译、可测试 |
| 4 | 新 `.c` ≤300 行 |
| 5 | 学生实现**不**编入默认 Kernel |
| 6 | 三架构可编（x86_64 / arm64 / riscv） |
| 7 | **不搬** BSS 敏感全局（`gTasks` / `gRunQueue` / `gIdleSlot` / `gSegments` / `gPhysLock` 留在框架） |
| 8 | 每阶段分刀；一次只做一刀 |

## 四、阶段 2 · 物理内存分配器

> **目标**：与调度器同模式——`MEMORY_OPS` + `MEMORY=` + Host 单测 + 学生模板。  
> **不改** `PhysicalMemory.h` 对外签名。现网无独立 Heap；可替换面就是 PMM 页分配政策。  
> **前置**：[`PR-PMM-sparse`](../路线图.md#done-pr-pmm-sparse) ✅ GD（2026-09-24）——段表已稳定，本柱可开。

### 4.1 现有结构（2026-09-24 核对）

| 文件 | ~行 | 职责 |
| ---- | --: | ---- |
| `Include/PhysicalMemory.h` | 26 | 对外 API：Init / Alloc(Pages) / Free(Pages) / Retain / Release / Total / FreeCount |
| `Include/PhysicalMemoryPrivate.h` | 26 | `PMM_SEGMENT`、段常量、`PmmSegment*` |
| `Core/PhysicalMemory.c` | 26 | `PhysicalMemoryInitialize`：锁 init + `PmmSegmentInit` |
| `Core/PhysicalMemorySeg.c` | 281 | **段表**：boot 区域涂色、bitmap/refcount 分配、`PmmSegment()` |
| `Core/PhysicalMemoryAlloc.c` | 256 | **分配政策 + 锁**：`SegmentFindFreeRange`、Alloc/Free/Retain/Release、Total/FreeCount |

构建：`CORE_SRCS := $(wildcard Core/*.c)` 已链上述文件；**尚无** `MEMORY=`、`MEMORY_OPS`、`Common/Modules/PhysicalMemory*`。`SCHEDULER=` 已是显式列表范本（见 Makefile）。

### 4.2 政策 vs 框架

| 政策（进 Ops，可替换） | 框架（不动语义） |
| ---- | ---- |
| `Init`（默认 Bitmap：空实现） | `PMM_SEGMENT` / `gSegments` / boot 涂色（`PhysicalMemorySeg.c`） |
| `AllocPagesLocked`（段扫描 + FindFree + 置位 + Ref=1） | `gPhysLock`；公开 API 加锁后调 Ops |
| `FreePagesLocked` | `Lookup(Phys→Seg,Idx)`；`PMM_DIRECT_BYTES` 恒等上限 |
| `RetainPageLocked` / `ReleasePageLocked` | `PhysicalMemoryInitialize` 顺序（见 §4.4）；Total/FreeCount 聚合 |
| `FindFreeRange` 策略（默认 first-fit） | bitmap / RefCount **存储**仍挂在段上（v1 不换存储外形） |

调用约定：Ops 的 Alloc/Free/Retain/Release **假定框架已持 `gPhysLock`**（同调度器 Enqueue/Remove）。实现**不应**再加锁。

### 4.3 `PhysicalMemoryAlloc.c` 函数分类（第 1 刀前已交）

对照 `Core/PhysicalMemoryAlloc.c`（256 行）实况：

| 函数 / 符号 | 分类 | 说明 |
| ---- | ---- | ---- |
| `gPhysLock` / `PmmPhysLockInit` | **框架** | 锁生命周期；公开 API 加解锁 |
| `PMM_DIRECT_BYTES` | **框架** | 恒等映射可返回窗口（x86 512MB / 他拱 4GiB） |
| `SegmentFindFreeRange` | **政策** | 段内 first-fit 找连续空闲；第 2 刀随政策迁 Modules |
| `Lookup` | **框架** | Phys→Seg+Idx；政策可调用，第 2 刀可升为框架辅助导出 |
| `PhysicalMemoryAllocatePages` | **混合** | 外壳：`Count==0`/加解锁/失败 `DebugWrite` = 框架；段循环+FindFree+置位+Ref=1 = 政策 → `AllocPagesLocked` |
| `PhysicalMemoryAllocatePage` | **框架** | 薄封装 → `AllocatePages(1)`，不进 Ops |
| `PhysicalMemoryFreePages` | **混合** | 外壳：空参/对齐/加解锁/越界警告 = 框架；段内清位或降 Ref = 政策 → `FreePagesLocked` |
| `PhysicalMemoryFreePage` | **框架** | 薄封装 → `FreePages(...,1)` |
| `PhysicalMemoryRetainPage` | **混合** | 外壳：空参/对齐/加解锁 = 框架；Ref++ 与失败码 = 政策 → `RetainPageLocked` |
| `PhysicalMemoryReleasePage` | **混合** | 外壳 = 框架；Ref--、至 0 清位 = 政策 → `ReleasePageLocked` |
| `PhysicalMemoryTotalPages` | **框架** | 聚合各段 `PageCount`，**不进 Ops** |
| `PhysicalMemoryFreePageCount` | **框架** | 聚合各段 `FreePages`，**不进 Ops** |

**现网 vs Ops 契约差异（须在第 1 刀改齐）**：

| 点 | 现网 `PhysicalMemoryRetainPage` | Ops 契约 `RetainPageLocked` |
| -- | ---- | ---- |
| RefCount 已为 `0xFFFF` | 仍返回 `0`（不自增） | 返回 `-1` |

饱和在现网几乎不可达；第 1 刀按 Ops 契约改为 `-1`，属契约澄清，验收写明即可。

### 4.4 `MemoryOpsRegister` 调用时机

`PhysicalMemoryInitialize` 目标顺序：

1. `gPhysLock` 初始化（`PmmPhysLockInit`）
2. `PmmSegmentInit`（**框架**，不使用 Ops）
3. `MemoryOpsRegister(MemoryBitmapOps())`
4. `Ops->Init()`（政策侧初始化）
5. 其它（现网：打印 free/tracked）

**关键**：`PmmSegmentInit` 在 Ops 注册**之前**执行，不调用任何 Ops 入口。

### 4.5 `MEMORY_OPS` 完整定义（已确认）

```c
/* Include/MemoryOps.h */
#ifndef MEMORY_OPS_H
#define MEMORY_OPS_H

#include "BootTypes.h"

typedef struct {
    /*
     * Init：政策侧初始化
     *   - 默认 Bitmap 政策：空实现
     *   - 学生政策：初始化自己的数据结构
     *   - 调用时机：PmmSegmentInit 之后
     */
    void (*Init)(void);

    /*
     * AllocPagesLocked(Count)
     *   - Count == 0 → 返回 NULL
     *   - 无空闲连续页 → 返回 NULL
     *   - 成功 → 返回物理地址（恒等映射下的虚拟地址）
     *   - 调用约定：框架已持 gPhysLock；实现不应再加锁
     */
    void *(*AllocPagesLocked)(UINT32 Count);

    /*
     * FreePagesLocked(Page, Count)
     *   - Page == NULL 或 Count == 0 → 空操作
     *   - Page 不在任何段 → DebugWrite 警告，空操作
     *   - 调用约定：框架已持 gPhysLock
     */
    void (*FreePagesLocked)(void *Page, UINT32 Count);

    /*
     * RetainPageLocked(Page)
     *   - Page == NULL → 返回 -1
     *   - Page 不在任何段 → 返回 -1
     *   - Page 未分配（RefCount == 0） → 返回 -1
     *   - RefCount 饱和（0xFFFF） → 返回 -1
     *   - 成功 → 返回 0
     *   - 调用约定：框架已持 gPhysLock
     */
    int (*RetainPageLocked)(void *Page);

    /*
     * ReleasePageLocked(Page)
     *   - Page == NULL → 空操作
     *   - Page 不在任何段 → DebugWrite 警告，空操作
     *   - Page 未分配 → DebugWrite 警告，空操作
     *   - RefCount 减到 0 → 清位图位 + FreePages++
     *   - 调用约定：框架已持 gPhysLock
     */
    void (*ReleasePageLocked)(void *Page);
} MEMORY_OPS;

void MemoryOpsRegister(const MEMORY_OPS *Ops);
const MEMORY_OPS *MemoryOpsGet(void);
const MEMORY_OPS *MemoryBitmapOps(void);

#endif
```

文件落点（与调度器对称）：

```
Include/MemoryOps.h
Include/PhysicalMemory.h              # 对外 API 不动
Core/PhysicalMemoryOps.c              # Register / Get（≤50 行）
Core/PhysicalMemoryAlloc.c            # 第 1 刀：实现仍在此，经 gOps 转发
Common/Modules/PhysicalMemoryBitmap/  # 第 2 刀迁入
```

公开 API 形态（第 1 刀）：加锁 → `MemoryOpsGet()->XxxLocked(...)` → 解锁。`AllocatePage` / `FreePage` 仍为薄封装。

### 4.6 Makefile 片段（第 2 刀起落地；第 1 刀不加 `MEMORY=`）

仿现网 `SCHEDULER=`（显式列表，禁 wildcard）：

```makefile
MEMORY ?= bitmap

ifeq ($(MEMORY),bitmap)
    MEMORY_SRCS := Common/Modules/PhysicalMemoryBitmap/PhysicalMemoryBitmap.c
else ifeq ($(MEMORY),bestfit)
    MEMORY_SRCS := Student/PhysicalMemoryBestFit/PhysicalMemoryBestFit.c
else
    $(error Unknown MEMORY: $(MEMORY))

# 链入 OBJS（勿 CORE_SRCS wildcard 扫 Modules/Student）
MEMORY_OBJS := $(patsubst %.c,$(BUILDDIR)/%.o,$(MEMORY_SRCS))
```

**不用** wildcard 扫 `Modules/` 或 `Student/`。第 1 刀只加 Ops 胶水，实现仍链在 `Core/PhysicalMemoryAlloc.c`（已被 `Core/*.c` wildcard 覆盖）；`MEMORY=` 与 Modules 文件在 **PR-MEM-move** 引入。

### 4.10 风险

| 风险 | 对策 |
| ---- | ---- |
| wildcard 误链学生 | `MEMORY=` **显式**列表（同 `SCHEDULER=`） |
| COW / RefCount 弄坏 | Retain/Release 进 Ops 但存储仍用段 RefCount；单测覆盖 |
| 恒等映射越界 | `PMM_DIRECT_BYTES` 裁剪留框架（可在框架外壳或 Locked 内，第 2 刀分类时钉死） |
| 与 `PR-PMM-sparse` 混淆 | 稀疏化已 GD；本柱只做可替换 Ops，不改段表外形 |
| Retain 饱和返回值 | 现网 `0` → Ops `-1`；第 1 刀改齐并写验收 |
