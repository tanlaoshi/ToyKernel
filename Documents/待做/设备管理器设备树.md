### 2.1 `Include/Device.h`

| 项 | 现状 |
| -- | ---- |
| **`Parent`** | **已有**；枚举后恒 NULL |
| Children / ChildCount | **无**（本柱也**不加**） |
| `DeviceSetParent` 等 | **无** → 第 1 刀补 |

### 2.2 `Core/Device.c`

- `gDevices[DEVICE_MAX]`，`DEVICE_MAX=128`。  
- `DeviceAdd` 按值拷贝，**会拷贝** `Parent`；建边必须在 Add 之后对**表内指针**调用 `DeviceSetParent`。

### 2.3 `HAL/X64/DeviceEnum.c`

- Bus 0..255 扁平扫；Class 只用于短名。  
- **不**读桥总线号、**不**设 Parent。  
- 下游设备已在表中，缺的是边。

### 2.4 `lsdev`

- 扁平 `DeviceListDump`；无 `-t`。

### 2.5 PCI 桥识别

| 条件 | 含义 |
| ---- | ---- |
| Class `0x06` | Bridge |
| Subclass `0x00` | Host Bridge |
| Subclass `0x04` | PCI-to-PCI / PCIe Root Port 等 |

类型 1 配置 `0x18`：

| 字节 | 字段 |
| ---- | ---- |
| 低 | Primary Bus |
| 次 | **Secondary Bus** |
| 高 | **Subordinate Bus** |

只读配置；**不写** Command / BAR。

## 三、设计（按已确认决策）

### 3.1 策略 A：只 Parent + 扫表

```c
void DeviceSetParent(DEVICE_NODE *Child, DEVICE_NODE *Parent);
DEVICE_NODE *DeviceGetParent(DEVICE_NODE *Dev);
/* 扫 gDevices：Parent==Me 的填入 Out[0..Max)；返回个数 */
int DeviceGetChildren(DEVICE_NODE *Parent, DEVICE_NODE **Out, int Max);
```

| 规则 | 说明 |
| ---- | ---- |
| 表内指针 | `Parent` / `Child` 必须是 `DeviceGet(i)` 结果，禁止栈上节点 |
| 校验 | `SetParent`：两指针落在 `gDevices[]`；简单环检测（沿 Parent 链） |
| 清空 | `Parent==NULL` 表示摘下（允许） |

**不做** `Children[]`：容量不够、双写易烂、Add 顺序难。

### 3.2 枚举两趟

```text
1) HalDeviceEnumerate：现有扁平 DeviceAdd（Parent=NULL）— 行为不变
2) HalDeviceLinkPciTree()：只读配置 + DeviceSetParent
```

第 2 步放独立 `.c`，末尾由 `HalDeviceEnumerate` 调用一次。

### 3.3 建边算法（写死）

```text
/* A. PPB / Root Port */
对每个桥 Br (Class=0x06, Subclass=0x04 等，可读 Sec/Sub):
  读 Sec, Sub
对每个设备 Dev (!= Br, Bus==PCI):
  若 Dev.PciBus ∈ [某桥 Sec, Sub]:
    Parent = 候选中 Secondary 最大且 Secondary ≤ Dev.PciBus 的桥
    DeviceSetParent(Dev, Parent)

/* B. Host 浅挂（已确认：要） */
找 Host = 第一个 Class=0x06/Subclass=0x00（若多个：PciBus==0 优先）
对每个 Dev:
  若 Dev.Parent==NULL 且 Dev!=Host 且 Dev.PciBus==0:
    DeviceSetParent(Dev, Host)
```

- Host 自身 `Parent==NULL`（树根）。  
- 已挂在 Root Port 下的设备（`Parent≠NULL`）**不再**改挂 Host。  
- 顺序：先 A（桥），再 B（Host 浅挂）。

### 3.4 与阶段 1/2

- 树打印：有 FriendlyName（阶段 1）用其，否则 `Name` + `[bus:dev.fn]`。  
- 拓扑不依赖 Match；可与阶段 2 并行实现。  
- USB 功能设备不进本树。

### 3.5 验收机期望

| 机 | 期望 |
| -- | ---- |
| QEMU | Host 下挂 VGA/网卡等；若有 PCIe 口则「桥 → 下游」 |
| NUC | 多个 Root Port；手测 `-t`；深度上限 16 防爆 |

## 四、PR 拆分（3 刀）

| 序 | PR | 交付 | 验收 |
| -- | -- | ---- | ---- |
| **1** | **PR-DEV-tree-api** | 三 API；头文件注释写明策略 A | build + smoke；调试可 SetParent 后 GetChildren |
| **2** | **PR-DEV-tree-pci** | `HalDeviceLinkPciTree`；最近桥 + Host 浅挂 | QEMU **至少 1 条** `Parent≠NULL`；串口可选 dump 边数 |
| **3** | **PR-DEV-tree-lsdev** | `lsdev -t` / `list devices -t`；`PrintDeviceTree` | 树可读；无 `-t` 仍扁平；**不**改 DevicesUi |

**依赖**：1 → 2 → 3。

### 第 1 刀 · API（细节）

- 实现放 `Core/Device.c`（或 `DeviceTree.c` 若行数紧）。  
- `DeviceAdd` 现有 `Parent` 拷贝保留（兼容）；正常路径建边走 `SetParent`。

### 第 2 刀 · PCI 链接（细节）

- 识别 Host：`0x06/0x00`；PPB：`0x06/0x04`（其它 `0x06` 子类：有有效 Sec/Sub 则按桥处理，否则跳过）。  
- **不写**任何 PCI Command。

### 第 3 刀 · `lsdev -t`（细节）

- 解析 `-t`；根 = `Parent==NULL`。  
- 缩进 2 空格 × Depth；递归 Depth≥16 停止并串口警告。  
- `-t` 与阶段 1 的 `-v` 等：**可组合**；树模式下仍可用 verbose 行格式（实现时一行内解决，勿拆旗标战争）。

示意：

```text
[00:00.0] Host bridge
  [00:01.0] VGA
  [00:02.0] Virtio network
  [00:1c.0] PCI bridge
    [01:00.0] ...
```
