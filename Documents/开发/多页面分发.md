# 多页面分发组织

> 状态：规范。配套：应用开发指南 §5.5、API速查 §GUI、如何写一个任务管理器App.md。  
> 目标：按钮事件是全局扁平 ID，业务分页面；本文给出三种组织方式、ID 分配策略、设计器边界。

---

## 1. 问题

- `ToyUiPoll` 返回的事件带 ID
- 应用可能有多个页面（Home / Settings / About / Files）
- 如果所有 `OnIdXxx` 堆在一个文件，20 个页面 = 200 个函数
- 需要按页面组织函数，用一层薄分发把事件路由到对应页面

两层 ID：物理（`ToyUi.h` 按钮 0..3 等）↔ 逻辑（应用枚举，§3）。切页 `Create`/`Destroy` 重绑物理槽。

---

## 2. 三种组织方式

### 2.1 方式 1：单页面单文件（最简单，推荐先学）

适用：控件 &lt;10 个/页；页面 1–3 个。

```c
/* PageHome.c */
void HomeOnRefresh(int Wid) { ... }
void HomeDispatch(int Wid, int Ev) {
    if (Ev == TOY_UI_BUTTON_EVENT(0)) HomeOnRefresh(Wid);
    else if (Ev == TOY_UI_BUTTON_EVENT(1)) HomeOnNext(Wid);
}
/* main：入门可 HomeDispatch+SettingsDispatch；页多改 §2.2 / §4 */
```

可行性：**高** · 预估：每页 50–150 行 · 破 ABI：**否**

### 2.2 方式 2：页面表 + 函数指针（页多时推荐）

```c
typedef struct {
    void (*Create)(int Wid);
    void (*Destroy)(int Wid);
    void (*Dispatch)(int Wid, int Ev);
} APP_PAGE;
/* gPages[PAGE_HOME]=...；环见 §4 */
```

可行性：**高** · 预估：表+路由 30–80 行 · 破 ABI：**否**

### 2.3 方式 3：函数指针表（控件 &gt;30）

页内 `OnId` 也表驱动（逻辑 ID → 函数），避免巨型 `if-else`。可行性：**中** · 预估：+80–150 行 · 破 ABI：**否**

---

## 3. 三种 ID 策略

### 3.1 策略 A：按页面分区间（推荐）

| 页面 | ID 区间 |
| ---- | ------- |
| Home | 1000–1099 |
| Settings | 1100–1199 |
| About | 1200–1299 |
| Files | 1300–1399 |
| 全局导航 | 9000–9099 |

好处：区间快速路由；设计器按页分段；增删页不影响其它页 ID。

### 3.2 策略 B：密排

从 1 递增不留洞——短时省事，插页重编号。课上 ≤2 页可凑合；正式用 **A**。

### 3.3 策略 C：物理槽直绑

逻辑名仅注释，`Dispatch` 只认 0..3。无设计器、单页够用；多页易糊。

物理槽永远 0..3；与逻辑区间无关。`Create` 做「逻辑 → 槽」。

---

## 4. 页面切换

全局导航用独立 ID（如 `ID_NAV_SETTINGS = 9000`）。`gCurrentPage` 记当前页。**导航事件优先于页面事件**。

```c
enum { PAGE_HOME, PAGE_SETTINGS };
enum { ID_NAV_SETTINGS = 9000 }; /* 全局导航，§3.1 */
static int gCurrentPage = PAGE_HOME;

for (;;) {
    int Ev = ToyUiPoll(Wid);
    if (Ev == TOY_UI_EVENT_NONE) { sched_yield(); continue; }
    /* 示意：逻辑 ID；若 Poll 仅物理槽，则用固定槽（如 3）表示导航 */
    if (Ev == TOY_UI_BUTTON_EVENT(ID_NAV_SETTINGS)
        || Ev == ID_NAV_SETTINGS) {
        gPages[gCurrentPage]->Destroy(Wid);
        gCurrentPage = PAGE_SETTINGS;
        SettingsCreate(Wid); /* 或 gPages[PAGE_SETTINGS]->Create */
        continue;
    }
    gPages[gCurrentPage]->Dispatch(Wid, Ev);
}
```

要点：导航按钮不属于任何页面；切页先 `Destroy` 旧页再 `Create` 新页；切页事件不传给页面 `Dispatch`。

## 5. 设计器能生成什么、不能生成什么

| 能生成 | 不能生成 |
| ------ | -------- |
| ID 枚举（按页面分组） | 每个 ID 对应的处理函数体 |
| 控件数组 | 处理函数里的业务逻辑 |
| 分发表的「事件列」 | 分发表的「函数列」 |
| `Dispatch` 空壳 | 空壳里 if-else 的内容 |
| 动作桩声明与空实现 | 动作桩里的业务逻辑 |

动作桩形状：

```c
void OnIdRefresh(int Wid) { /* TODO */ }
void OnIdNext(int Wid)    { /* TODO */ }
```

学生只需填 `/* TODO */`。

---

## 6. 推荐路径

1. 先单页面 if-else 分发（1 页，3–5 个控件）  
2. 再多页面结构体（3–5 页，§2.2 + §4）  
3. 再函数指针表（控件 &gt;30，§2.3）  
4. 再设计器生成 ID + 空壳 + 动作桩（§5）

---

## 7. 常见错误

| 错误 | 正确做法 |
| ---- | -------- |
| 所有 `OnIdXxx` 堆一个文件 | 按页面分文件 |
| ID 全局递增无区间 | 按页面分区间（§3.1） |
| 导航事件传给页面 | 导航优先处理，不传页面 |
| 切页不 `Destroy` 旧页 | 先 `Destroy` 再 `Create` |
| 设计器生成业务逻辑 | 设计器只生成空壳，逻辑学生填 |
