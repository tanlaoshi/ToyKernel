# 用户态线程（PR-U-thread · 活文档）

> **目的**：同一进程内多执行流（教学版线程子集）——**课上能讲清、demo 能跑通、作业能写小程序**，不是 Linux 兼容层。  
> **排期指针**：路线图 ★ 空；缺口原 **D.3**；候补见 [`../路线图.md#sec-exec-plan`](../路线图.md#sec-exec-plan)。  
> **权威代码（目标）**：`Core/Scheduler*` + `Core/Process*` + `User/` CRT；syscall 进 `SyscallABI.h`。  
> **日期**：2026-09-29 · **规划稿**（未 JX）。

| 问 | 答 |
| -- | -- |

## 0.1 教学级别能干什么

**定位**：操作系统课「进程 vs 线程 / 共享内存 / 同步入门」实验平台，不是跑 Redis/Chrome。

### 学生能亲手做的

| 能力 | 课上怎么用 | 对应 API（名可微调） |
| ---- | ---------- | ------------------- |
| 创建线程 | `THREADDEMO`：主线程 + worker | `pthread_create` / `toy_thread_create` |
| 等待结束 | join 后收结果 | `pthread_join` |
| 线程退出 | worker `return` / `pthread_exit` | `thread_exit` |
| 共享内存 | 两线程读写同一全局/`malloc` 缓冲（同地址空间） | 无需额外 API |
| 私有数据 | 每线程 TLS 槽（如 `errno` 风格、线程本地计数） | TLS / `__thread` 最小集 |
| 互斥 | 保护共享计数，演示「不加锁会花」 | `pthread_mutex_lock/unlock`（**自旋教学版**即可） |
| 辨身份 | 打印 pid 相同、tid 不同 | `getpid` + `gettid` |
| 与进程对照 | 单线程仍可 `fork`；多线程 `fork` **失败**并讲清为何 | 现有 `fork` + 本柱策略 |

### 课堂三条标准故事（验收时 demo 覆盖）

1. **计数器**：两线程 `N` 次 `++`；无锁结果偏小，加 mutex 正确 → 讲竞争。  
2. **流水线**：线程 A 填缓冲、线程 B 读缓冲（自旋 mutex 或「先 join 再读」简化版）→ 讲共享地址空间。  
3. **身份**：同进程两线程 `getpid` 相同、`gettid` 不同；对比再 `fork` 出的子进程 → 讲线程 vs 进程。

### 作业量级（开课可布置）

- 实现「主线程创建 2～4 个 worker，各自算一段，join 汇总」。  
- 可选：给共享队列加 mutex，故意去掉锁看错结果。  
- **不要求**：写网络服务器线程池、GUI 强制多线程化。

### 子集刻意不包含（仍够教学）

| 不做 | 课上怎么交代 |
| ---- | ------------ |
| `pthread_cond` / 读写锁 / 取消点 | 「同步还有条件变量，本学期用 mutex+轮询/join 代替」 |
| 多线程进程里 `fork` 出完整 Linux 语义 | 「ToyOS 直接禁止，逼你先理解危险」 |
| 信号哪个线程吃 | 「信号模型未产品化；课用轮询标志位」 |
| 任意 Linux 二进制 | 「必须本 SDK/CRT」 |

### 一句话给学生卡

> ToyOS 线程子集：能 **create / join / 共享内存 / TLS / mutex**，用来搞懂线程；不能当 Linux 线程库用。

### 和「桌面更流畅」的关系（常见误判）

| 想法 | 实际情况（ToyOS） |
| ---- | ----------------- |
| 有了线程 GUI 就能多线程收输入、自然更顺 | **输入已经是独立内核任务**（`InputTask` + 可选专核），不是缺用户态线程。再拆用户线程收输入，要加锁，**更容易卡/竞态**。 |
| worker 多线程同步算，界面不卡 | **对用户 App 成立**：重活放 worker，主线程只画/收事件——前提是重活别占着 Gui 大锁 / 别在 Present 路径上算。 |
| 分角色：谁专门负责啥 | **进程/任务级已经在分**：Shell / Gui / Input / 网卡泵等是不同 `TASK`。线程适合 **同一 App 内** 分角色（下载线程、解码线程），不是先重写整个桌面成线程池。 |
| 线程 ≈ 多核加速拖窗 | 拖窗流畅主要靠 **Present/blit/翻页**（igpu 柱）和少在 UI 路径做阻塞 IO；线程帮不上 GPU。 |

**结论**：线程柱的教学/工程价值是 **App 内并发与课纲**；要桌面更顺，优先继续砍 **UI 路径上的阻塞与临界区**，而不是「Gui 改成很多线程」。

## 1. 现状与红线

**现在（相关）**

- 可调度单位是 `TASK`（`Include/Scheduler.h`）：已有 `UserSpace`、`PageRoot`、FD、信号槽、亲和性。
- 用户进程经 `SchedulerCreateUser` / `fork` 来；**无**「共享 mm 的第二执行流」。
- CRT / `LIBTOY.SO`：**无** TLS；动态库仅 JUMP_SLOT（D.3）。
- `MAX_TASKS=16` 偏紧——本柱至少要规划 **抬上限或线程槽另计**。

**红线**

- **不**承诺 Linux 线程 ABI；不跑任意 Linux pthread 程序。
- **不**做内核抢占式驱动线程池产品化（Store 后台等仍按现策略）。
- `fork` 在多线程进程中的语义必须 **写死一种**（见 §2），禁止含糊。
- 新 `.c` ≤300；三架构可编；`smoke-boot` + 线程 demo 冒烟。
- 手册：调度/进程边界清晰；Gui 不直接碰调度锁。

## 2. 语义钉死（开写前必认）

| 题 | ToyOS 本柱选择 |
| -- | -------------- |
| 谁是「进程」？ | 一组共享同一 `VIRTUAL_ADDRESS_SPACE*` 的用户 `TASK`；**主线程** = 组内第一个（或 `ThreadGroupId` 主人）。 |
| `getpid` | 返回 **进程/组 id**（稳定；兼容现有课）。 |
| `gettid` | 新 syscall：返回 **任务槽相关 tid**。 |
| `fork` | **推荐**：若组内线程数 >1 → **失败**（`EAGAIN`/`EINVAL`）；单线程进程行为与今日一致。（备选「只拷调用线程」更像 Linux，但实现更重——本柱默认拒绝。） |
| `exec` | 组内其它线程 **终止**；地址空间换成新映像（与 Linux 同方向的最小子集）。 |
| `exit`（线程） | 只结束调用线程；组内最后一线程退出 ≈ 今日进程 `exit`。 |
| `exit`（进程） | 可选 `exit_group`：杀光同组线程（可与最后线程 `exit` 合并实现）。 |
| 信号 | 本柱 **最小**：维持现有 per-TASK 槽；不重做 POSIX 信号线程模型。文档写明「信号+多线程未产品化」。 |
| TLS | x86：`FS` 基（`WRFSBASE` 或 GDT）；每线程一块 TLS 模板；Arm64/RiscV 用各 arch TP 寄存器。 |
| 同步 | 本柱交付 **用户态自旋 + futex 最小集可选**；第一刀可不做 futex，CRT 先提供 `mutex` 自旋教学版。 |
