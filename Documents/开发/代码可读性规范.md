# 代码可读性规范

> 状态：规范。配套：开发命名规范.md、开发者接手指南.md、技术手册 §I。  
> 目标：让普通人学个 C 就能看懂 ToyOS。两条主线：结构上可读（分层）、字面上可读（长名字）。

## 1. 两条主线

| 主线 | 解决什么 | 本质 |
| ---- | -------- | ---- |
| 分层 | 谁依赖谁、执行顺序、主路径显式 | 结构上可读 |
| 长名字 | 名字即文档、不跳定义、不查表 | 字面上可读 |

合起来一句话：读代码不需要“查文档、跳定义、记缩写”。

## 2. 分层规范

### 2.1 三层结构

- 全局分层：Boot → HAL → Core → Services → User
- 模块内分层：主文件（编排）+ 分文件（实现）
- 函数内分层：主函数（顺序表）+ 辅助函数（一件事）

### 2.2 模块标准形状

每个模块按「主文件 + 主函数 + 分文件分函数」组织：

主文件只做三件事：

1. 定义对外 API（薄门面，每个 ≤15 行）
2. 定义主函数（≤30 行，顺序调分文件）
3. 调分文件里的函数

分文件按能力切，每个 **`.c`** ≤300 行，每个函数 ≤60 行。  
**`.md` / `Documents/**` 没有行数上限**——门槛只约束代码。

### 2.3 主函数是“顺序表”，不是“策略表”

主函数里只该有“做什么”，不该有“什么情况下做什么”。

| 该有 | 不该有 |
| ---- | ------ |
| `InitializeXxx()` 调用 | `if (HalHasFrameBuffer())` |
| `SchedulerCreate()` | `if (LWIP)` |
| `SchedulerStart()` | `if (UsbReady)` |
| `Teach()` 输出 | `#ifdef TOY_X64` |
| — | `if (Init() != 0) Halt()` |

分支下沉到三处：

1. 平台分发（KernelMain 一处）
2. 模块内部（各 Initialize 自己的软退）
3. 编译期宏（架构/配置）

### 2.4 按平台显式分路径

目标形状（教学示意；落地旗标见 §2.5）：

```c
int KernelMain(void) {
    if (HalPlatformIsVirtSerialConsole()) return KernelMainVirt();
    if (HalHasFrameBuffer())              return KernelMainVirtDesktop();
    return KernelMainFull();
}

int KernelMainFull(void) {
    InitializeSerial();
    InitializePhysicalMemory();
    InitializeDriver();
    InitializeVirtualMemory();
    InitializeVideo();
    InitializeCpu();
    InitializeSmp();
    InitializeUsb();
    InitializeFileSystem();
    InitializeNetwork();
    InitializeGui();
    InitializeScheduler();
    InitializeConsole();
    return KernelMainCommon();
}

int KernelMainCommon(void) {
    SchedulerCreate("shell");
    SchedulerCreate("gui");
    SchedulerCreate("worker");
    SchedulerStart();
    return 0;
}
```

`KernelMain` 只分发。`KernelMainFull` / `Virt` / `VirtDesktop` 只顺序调用。`KernelMainCommon` 只拉常驻任务。失败停机、无设备、无网卡：写在对应 `Initialize*` 里，主函数不出现 `if (… != 0) Halt()`。

### 2.5 对照现码（必须按这个分发）

现入口：`CodeC-Core/Kernel/Kernel.c` 的 `KernelMain`（`void`，由 `HAL/<Arch>/Startup.c` 调用）。它现在既做「尽早挂串口/FB」、又 `KernelModulesRun()`，再按平台 `KernelSpawn`——**一张策略表**。

模块表在 `KernelModules.c`，`Initialize*` 在 `KernelModulesInit.c`。`KernelModulesRun` 里的三路才是真旗标（`Hal.h`）：

| 路 | 现码条件 | 表 | 常驻任务（现码） |
| -- | -------- | -- | ---------------- |
| 串口子集 | `HalConsoleOnly()` | `gModulesVirt` | 单核直跑 `ConsoleSerialRun`；多核 spawn `shell` |
| virt 桌面 | `HalHasFrameBuffer()` 且 `HalPlatformIsVirtSerialConsole()` | `gModulesVirtDesktop` | shell / gui / worker；（CPU>2 才 `input`） |
| 全量 | 其余（x86 真机） | `gModulesFull`（含 USB、SerialEarly） | 同上 |

`HalPlatformIsVirtSerialConsole` 表示 **virt 平台形状**，不是「只有串口」。落地分发必须写成：

```c
int KernelMain(void) {
    if (HalConsoleOnly())
        return KernelMainVirt();
    if (HalHasFrameBuffer() && HalPlatformIsVirtSerialConsole())
        return KernelMainVirtDesktop();
    return KernelMainFull();
}
```

若先写 `if (HalPlatformIsVirtSerialConsole()) return KernelMainVirt();`，QEMU 有 GOP 时会走进无 Video/Gui 的路径。

现码还要把这些从 `KernelMain` 挪走（各进顺序表或模块内部，行为不变）：

| 现码在 KernelMain 里 | 下沉到 |
| -------------------- | ------ |
| 尽早 `HalSerialInitialize` / `HalVideoSet`（防 Console `Width=0`） | `KernelMainFull`/`VirtDesktop` 顺序最前，或 `InitializeFrameBufferEarly` |
| GOP 镜像日志、`FontInitialize`/`ThemeInitialize` | `InitializeVideo` / 串口 GOP 门面（已有幂等） |
| `KernelModulesRun() != 0` 则 `KernelParkForever` | 致命失败留在 `InitializePhysicalMemory` 等内部；主函数不 Halt |
| `FontSetById` + 关 GOP 镜像 | 进桌面前一步，放在对应路径函数末、Common 前 |
| `HalCpuCount() > 2` 才 spawn `input` | `InputTask` 自己软退，或 `InitializeScheduler` 内 |
| `KernelSpawn` 失败停机 | `SchedulerCreate` 包装成「失败即停」的门面，调用点仍一行 |

`InitializeCpu` 里 virt 才 `HalUsbInitialize`、`InitializeConsole` 里 `HalConsoleOnly` 选命令集：已在模块内部，符合 §2.3，不必抬到 `KernelMain`。

### 2.6 行数门槛（只约束代码）

| 对象 | 上限 |
| ---- | ---- |
| 主文件对外 API 每个函数 | 15 行 |
| 主函数（顺序表） | 30 行 |
| 任意函数 | 60 行 |
| 任一 `.c` | 300 行 |
| `.md`、`Documents/**`、讲义、路线图 | **无上限** |

存量 `.c` 超标不一次拆完；点名模块一刀一事。点阵、`ThirdParty/`、构建脚本仍走路线图原则 7（不按 300 拆），**不是**给文档加行数帽。

## 3. 长名字（字面上可读）

细则在命名规范 **§2.6**。此处只钉教学向三条：

1. 调用点读起来像句子：`InitializePhysicalMemory()`，不要 `InitPmm()`。
2. 能拼全词就不缩写；缩写只认命名规范 §七白名单（`USB`/`ELF`/`GOP`…）。
3. 公开 ABI、POSIX、寄存器名不借本规范改拼音或改语义。

## 4. 落地刀（规范入库后，点名再做；不改本文外的 ★）

每刀零行为（只搬家 / 只改名到全词）；`./build.sh`；动桌面则 `smoke-boot`。

| 刀 | 范围 | 一句话 |
| -- | ---- | ------ |
| **PR-K-seq-1** | `Kernel.c` | `KernelMain` 只三路分发；抽出路径函数；仍调 `KernelModulesRun`（**✅ TG**，手测进桌面） |
| **PR-K-seq-2** | `KernelModules.c` | 去掉 `Run` 内 if；`RunVirt` / `RunVirtDesktop` / `RunFull` 各绑一张表（**✅ TG**） |
| **PR-K-seq-3** | `Kernel.c` 任务段 | spawn 失败与 `input` 软退下沉；`Common` 只剩 Create+Start |
| **PR-K-seq-4** | `KernelModulesInit.c` | `InitializeVideo` / `Usb` / `Gui` 超 60 行的按能力拆分文件 |

不要在本柱改 syscall、模块表相对顺序（USB 在 FS 前等现码约束）、三架构链接。

## 5. 不做

- 不把标识符改成拼音
- 不把 `gModules*` 合成一张表再在表内 if
- 不把 Halt 策略改成「内存失败也继续」
- 不在 `KernelMain` 新加 `#ifdef TOY_X64`
