## 1. 现在能干什么（产品 / 课堂）

**课堂主路径是 x86 QEMU + ToyImage**，不是「三架构同一套桌面」。加电链路是：OVMF（UEFI）→ ToyBoot（`BOOTX64.EFI`）→ `Kernel.elf` → 模块表 → GOP 桌面 / Shell。学生能看见固件把控制权交给引导、引导把 ELF 内核搬进内存、内核开分页/中断/调度、用户 ELF 经 syscall 读写文件与控制台。入口：`ToyImage/run-split.sh`（盘 0 = ESP，盘 1 = `rootfs/`）；无头冒烟 `smoke-boot.sh`。

这条路径上已经能用的东西：

| 面 | 现状（归档级） |
|----|----------------|
| 桌面 | GOP 帧缓冲；标题栏 / 拖动 / 重叠合成；桌面图标双击开 Shell、Settings、Files |
| 主题 | `TOYOS.DB` KV + 仍写 `THEME.CFG`（Boot 读 `mode=`）；颜色 / 点阵字体 / 分辨率偏好（改分辨率须退出 QEMU 再跑脚本） |
| 存储 | Block + GPT + FAT（8.3+LFN、`.`/`..`、`mkdir`/`rmdir`）；多卷前缀 `TOYOS:` / `ESP:` / `A:`；识盘靠卷上 `TOYOS.ID`；**F3** 只读 `RES:` 资源卷 |
| 文件浏览器 | 进目录、预览、`.ELF` 打开；删除 / 新建 / 重命名 |
| 用户态 | Ring 3 ELF：`fork`（COW）/`wait`/`execve`/`pipe`/`dup`/`brk`/`kill`；CRT 最小集 + `CAT`/`WRITE`；简易 `.so`（JUMP_SLOT） |
| 语言 | UTF-8 绘制 + 教学用 CJK 点阵子集；UI 字符串表 `lang=en\|zh` 可持久化 |
| 网络 | virtio-net；builtin UDP/TCP（ping / echo / listen）；`LWIP=1` 时用户 socket（`NETDEMO`/`NETSRV`） |
| SMP | 演示级：AP 拉起、每核 idle、可偷 READY 任务；**shell / gui 钉在 BSP** |

**Arm64 / RiscV 是另一条 virt 骨架，不是 ToyImage / OVMF。** 入口是 `./build.sh arm64|riscv` + `run-virt-arm.sh` / `run-virt-riscv.sh`，QEMU `-kernel`（自有 Boot：DTB / OpenSBI）。**1.2d 已齐**：ramfb + virtio-input + virtio-blk + 同一套 Common Gui；默认开窗口（无 `DISPLAY` 回退 `--headless`）；`smoke-virt.sh` 无头冒烟。串口子集仍可用 `TOY_VIRT_SERIAL=1`。**1.2e N9/N10 ✅**：桌面挂 `net` + 默认 virtio-net + `ping 10.0.2.2`。**1.2f A10～A15 ✅**：真 MMU；用户态/syscall；本 arch `HELLO.ELF`；真 IRQ/timer；virt `HalSmp*`；HalFrame 命名中立。

已知课堂边角：QEMU 改分辨率须退出重跑；宿主极忙时 AP 仍可能超时（已 `--kill-qemu` / 单核降级 / Guest 单核继续）。

## 3. 分层原则（已写入文档的理想）

依赖只允许向下。硬规则已经写进 [`架构分层.md`](技术手册.md#i-体系结构)，实现时按回归看，不要把驱动头漏进 Common；UEFI 类型只留在 x86 Startup。

```
User → (syscall) → Core / Services
Services → Core / Library / Font / Hal*
Core → Library / Font / Hal* / BOOT_INFO
HAL/<Arch>/ 实现 + Drivers（私有头不进 Include/）
Boot：各 Arch 自有路径 → Startup 填 BOOT_INFO
```

- **HAL** 收纳全部架构代码（GDT、页表位、PL011 vs COM1、GIC vs LAPIC、ramfb vs GOP）。
- **Common 只消费 `BOOT_INFO` + `Hal*`**，禁止 `#include HAL/<Arch>/Drivers/*.h`，禁止写死 `EM_X86_64` / UEFI 类型。
- **Boot**：x86 继续 UEFI + ToyBoot + OVMF；**Arm64 / RiscV 自有 Boot**（virt + DTB / OpenSBI `-kernel`）。
- 相同 GUI = **Common Gui**。亮屏是该 Arch 的 **HAL Video**（virt 上 ramfb 或 virtio-gpu，不是 GOP）。块设备在该 Arch HAL 注册 virtio-blk，再接已有 Common FAT。

模块主线（x86 全表）：`serial → memory → driver → virtual-memory → video → cpu → smp → file-system → usb → network → gui → scheduler → console`。Video 先于读库；识盘（`TOYOS.ID`）≠ 数据库（`TOYOS.DB`）。virt 桌面：video / file-system / **network（N10）** / 输入 / gui / **smp（A14）**；串口子集亦挂 smp。

### 5.1 GUI（控件、视觉、热分辨率）

**现状**：x86 上已经有即时绘制的窗口管理器（`Gui.c`）：最多 6 窗、标题栏 40px、拖动与重叠合成、桌面三图标（Shell / Settings / Files）、Settings 文字菜单、Files 列表。点阵字体 + 教学 CJK 子集；颜色是 `0x00RRGGBB`。`UI.c` 里已有按钮/进度条原语；**G11** ✅ 已浅接入 Settings 边框与 Files 空状态/焦点行，**未**全面控件化。无开始菜单、无图标拖放、无壁纸位图、无 TTF。

**缺口**：把 Settings / Files / Shell 从「能用的教学窗」做成可讲的桌面产品，需要布局与状态（悬停、焦点、无图标占位），而不是再堆几个 `FillRect`。**1.2e G11** ✅ 浅接入已做；控件库全面接入（**G12**）仍可加深。**G-hotres ✅**：QEMU 上 Settings 可热切分辨率（Bochs）；不替代 D7 写盘。virt 上同一套 Gui 已属 **1.2d V5**；GUI 大块剩下的是视觉与交互，不是「再移植一套窗口」。

**为何是大块**：绘制路径绑在内核服务线程上（`GuiTask`），没有用户态 toolkit，没有矢量字。改一处颜色容易，改信息架构（多窗、菜单、文件预览排版）会碰到合成、剪裁、备份脏区、点阵度量，必须按屏给规格，不能当普通 Web UI 迭代。

**已拆进路线图**：**1.3u**（Files 侧栏 + 右侧内容，U1～U3）。

### 5.2 网络

**现状**：x86 virtio-net 已能 ping、UDP、简陋 TCP echo；`make LWIP=1` 后用户态 socket（号 8～12）可跑 `NETDEMO`/`NETSRV`。`run-split.sh` 已 `hostfwd` 9000。Builtin 是教学栈；lwIP 是可选生产路径。

**缺口**：默认构建仍是 builtin（lwIP 要显式打开）；**N-dns ✅**（`LWIP=1` 时 DNS/`dns`）。virt **N9/N10** ✅：`HalNet` + 桌面挂 `net` + `ping 10.0.2.2`。用户程序不能当「小 Unix 网络课」的默认体验，除非课堂构建显式 `LWIP=1`。

**为何是大块**：协议正确性、RX 与调度、用户 ABI 仍是长线。N9/N10 只做 HAL + 挂网 + ping；DNS/错误码已穿插收官，不和本阶段抢同一刀。

### 5.3 硬盘支持

**现状**：x86 上 ATA PIO（Primary 主/从），Common 已有 Block / GPT / FAT；写文件上限 **8MiB**（**FS3** ✅）；多卷与只读 ESP 已做。课堂盘是 QEMU 的 vvfat / raw，不是安装器。

**缺口分两层**。（1）**virt 块设备** = 1.2d **V4** ✅。（2）**真硬盘**：**AHCI → H1 ✅**；**NVMe → H5 ✅**；USB MSC / 安装器仍后置。

**为何是大块**：Block 抽象已经在，缺的是**后端与启动介质故事**。V4 已让 virt 上 `ls`/`exec` 命令成立（本 arch 用户 ELF 仍待 MMU）；真机还要把固件、ESP、系统卷、写盘工具串起来。混在一个 PR 里会把「能 ls」和「能装机」缠死。

### 5.4 开发库（用户态 libc）

**现状**：`User/crt/` 是教学 CRT，不是 glibc：`printf` 子集、`malloc` 走 `brk`、`open/read/write/close`+`errno`、`fork/wait/pipe/dup/execve`。头文件在 `User/include/`，禁止链内核 `Common/`。动态库只有 JUMP_SLOT 的 `LIBTOY.SO`。

**缺口**：没有 `mmap`、没有信号全集（**1.2e P4** ✅ 已做简单 `kill`）、没有完整 stdio 缓冲与 locale、没有线程、`.so` 无 TLS/COPY。任务槽约 8；FD 打开时整文件读入。POSIX 课上能演示的是「syscall 形状」，不是「把 Linux 用户程序直接编过来」。

**为何是大块**：每加一类 API 都要内核 syscall + 页表/信号语义 + CRT + 演示 ELF + FAT 同步。P1～P3 已经把「成系统」的最小集做完；再往下按课单加小刀（如 `mmap`），**不是**朝完整 POSIX / 复刻 Linux 演进。

**已拆进路线图**：**1.3v**（库盘点 V1 + 简易编辑器 V2 + 工具链调研 **V3 ✅**；不做自研编译器）。

### 5.5 真 SMP

**现状**：x86 S1～S4 演示级——AP 活着、每核 tick、调度大锁、可偷任务。shell/gui **钉 BSP**（输入同步未做）。**virt A14** ✅：Arm PSCI / RiscV soft-release，`-smp 2` 见 `idle0`/`idle1`（演示级，不迁 shell/gui）。宿主忙时 x86 AP 超时已降级，不是「多核桌面稳定」。

**缺口**：把 `shell`/`gui` 迁到 AP；真机 IOAPIC / 中断路由。1.2d / **1.2e** 都不要求迁 AP。**S-lock ✅**：exit 拆页表已松锁；Priority 入队（非每核锁）。

**为何是大块**：教学上「看见 idle1」已经够讲 SIPI；真并行会碰到输入队列、合成锁、用户页表跨核。和 virt 亮屏不是同一阶段。

### 5.6 进程 / POSIX 子集（信号、`mmap` 等）

P1～P3 已从「完整 POSIX」里拆出 `execve` / 管道 / `brk`。**1.2e P4** ✅ 再拆出简单信号（`kill` + 默认终止）。留下的是：`mmap`、信号全集、swap、更多任务槽与真正的 FD 流式读写。这是用户态课的再下一台阶，依赖页表与调度，而不是再写几个演示 `*.c`。

### 5.7 真机

virt：显示/输入/盘 **1.2d**；网 **N9/N10**（virtio）+ **H4 e1000**。真机两条线：**1.3c ✅** ∥ **1.3b ✅**。手册：[`如何增加一个驱动.md`](技术手册.md#iii-驱动)、[`如何增加板级支持.md`](技术手册.md#ii-boot板级与真机)。手机明确不做。回归冒烟清单见路线图 **1.4 后置**（不新开柱）。

### 5.8 商店与可组合包

**现状**：**S0～S5 ✅**；**M1～M2 ✅**（`depends=` + `combo`/`uncombo`）。**已拆进路线图**：**1.3s ✅** + **1.3m ✅**。

## 6. 给 AI 的 UI 设计材料怎么给

内核 GUI 不是浏览器，也不是能加载 TTF 的桌面环境。绘制在 **`Gui.c` / `Desktop.c` / `SettingsUi.c` / `FilesUi.c`**，经 `HalVideo*` 写帧缓冲；`UI.c` 有几何原语但多数屏仍是立即模式的填矩形 + 点阵字。典型分辨率 **1280×720**（Settings 还可 800×600 / 1024×768 / 1600×900）；标题栏 **40px**；桌面图标 **48×48**、间距 28；最多 **6** 个应用窗；颜色 **`0x00RRGGBB`**（与 `UI.h` 的 `COLOR_*`、Theme 桌面/Shell 底色一致）。字体是注册表里的点阵（`FONT_FACE`），汉字走 **`Fonts/cjk16.c` 子集**，没有矢量、没有完整 Unicode。QEMU 上 Settings 可 **热切分辨率**（**G-hotres** / Bochs）；真机或热切失败仍走写盘 + 重启（D7）。

**最稳的组合（不要只给一种）：**

1. **标注图 / 截图（PNG 或 WebP）**  
   至少一张**整屏 1280×720** 布局：桌面底色、图标网格位置、任务外的空白、Shell / Settings / Files 窗的默认位置与大小。在图上画框写字：标题栏高度、客户区边距、列表行高、关闭钮。Agent 能直接看图；只丢 Figma 云端链接而不导出，仓库里经常打不开。

2. **短文字规格（Markdown 列表或小表，大约 20 行就够）**  
   写清：目标分辨率；色值（例如桌面 `0x00404040`、标题栏焦点/非焦点各一色）；字体约束（只用现有点阵 / 若需新字必须给码点列表，不能写「用思源黑体」）；分屏：**桌面 / Settings / 文件 / Shell 窗** 各有什么控件、对齐、间距。Theme 已是 `0xRRGGBB`，不要改成 CSS `rgb()` 当唯一来源。

3. **状态**  
   默认 / 悬停 / 按下 / 窗口焦点 / 非焦点 / **无图标或空目录**。一张海报只有「漂亮的默认态」，实现时悬停和空列表会瞎编。缺状态就再补小图或在规格里用两行描述。

4. **不要当作唯一来源的东西**  
   完整 PSD/多层源文件（Agent 抽不出像素网格）；「按这个 SVG/TTF 直接进内核」；只有情绪板、无尺寸；把 Web/Material 组件库当可粘贴代码。矢量可以当**设计意图**，落地仍是矩形 + 现有字形。

5. **放哪**  
   图放进仓库（建议 `ToyKernel/docs/ui/`，文件名带屏名：`desktop-1280.png`、`settings-font.png`）或直接贴进 Cursor 对话。**图 + 约 20 行规格** 比单独一张海报有用；只给文字没有图，布局比例容易偏。改的是内核 C，一次只指定一屏（先桌面再 Settings），并写明「不要引入 TTF / 不要新建用户态 GUI 进程」。

课堂如果只是改 Theme 色和文案：一张标注过的桌面截图 + 色值表即可。如果要动 Files 列表或 Settings 分页：必须给该窗客户区的网格和空状态，否则会和现有 `GuiCompose` / 窗备份路径打架。

<a id="sec-3-2"></a>
## 2. 工具链能同步吗？

**能，但不靠 Git。** `ToyKernel/tools/` 里下列目录已被 `tools/.gitignore` 忽略：

- `tarballs/` — 下载的压缩包（可拷贝，体积大）
- `extract/` — 解压后的 xPack GCC（**推荐同步或本机重解压**）
- `debs/` / `root/` — 可选本机 QEMU deb 解压树
- `qemu/` — 占位/本地用

### 方案 A：对端重新下载（干净、可复现）

版本与家里当前一致时，直接按 [`tools/README.md`](../tools/README.md) 的 `wget` + `tar` 即可。钉扎版本：

| 组件 | 版本 |
|------|------|
| RISC-V xPack | `riscv-none-elf-gcc` **13.2.0-2** |
| AArch64 xPack | `aarch64-none-elf-gcc` **13.2.1-1.1** |

公司机若已有系统包，可跳过 xPack：

```bash
sudo apt install gcc-aarch64-linux-gnu gcc-riscv64-linux-gnu \
  qemu-system-arm qemu-system-misc   # 或 qemu-system-aarch64 / riscv64
```

Makefile 会优先用 `tools/extract`，否则用系统 `*-linux-gnu-*` / `*-none-elf-*`。

### 方案 B：U 盘 / `scp` / `rsync` 拷贝（无外网或想完全一致）

只拷 **必要** 目录，例如：

```bash
# 在「有现成工具链」的一侧打包（约 2～3GB，视是否含 tarballs）
cd ToyKernel
tar -czf /tmp/toy-tools-extract.tgz tools/extract
# 可选：tar -czf /tmp/toy-tools-tarballs.tgz tools/tarballs

# 到另一侧
cd ToyKernel
tar -xzf /path/to/toy-tools-extract.tgz
# 确认：
ls tools/extract/xpack-aarch64-none-elf-gcc-*/bin/aarch64-none-elf-gcc
ls tools/extract/xpack-riscv-none-elf-gcc-*/bin/riscv-none-elf-gcc
```

**不要**把 `tools/root/`（解压的 Ubuntu QEMU）默认拷到另一台，除非两边 **glibc / 发行版接近**。跨发行版优先用对方系统的 `qemu-system-aarch64` / `qemu-system-riscv64`。

### 方案 C：只同步源码、工具链各管各的

完全可行。验收时：

- x86：系统 `gcc` + 系统 `qemu-system-x86_64`（走 ToyImage）
- Arm/RiscV：本机 apt **或** 本机 xPack，见上

## 3. 注意事项（易踩坑）

1. **不要提交** `Build/`、`tools/extract|tarballs|debs|root`、本机改过的 `THEME.CFG` / 临时 `rootfs` 垃圾。
2. **Arm64/RiscV 当前不经 ToyImage**：用 `ToyKernel/run-virt-*.sh`。RiscV 默认 **OpenSBI**（内核 @`0x80200000`）；`TOY_RISCV_BIOS_NONE=1` 才是旧 `-bios none` 对照。Arm：脚本 dumpdtb + loader。可用 `TOY_VIRT_MEM=512M` 验收 DTB 内存图。
3. **x86 仍以 ToyImage 为唯一日常入口**：`run-split.sh` / `smoke-boot.sh`；`build.sh`（x86）会同步 `Kernel.elf` 与用户 ELF 到 Image。
4. **两边 Git 身份 / SSH key 各自配置**；勿共享私钥。pull 用 `--ff-only`，有分叉先在本机理清再 push。
5. **QEMU 版本**：家里若用解压 deb（如 6.2），公司用发行版自带即可跑 bringup（x86 OVMF；Arm/RiscV `-kernel` / OpenSBI）。
6. **残留 QEMU 进程**：换机器无关，但同机多次跑 virt 可能残留；`run-virt-*.sh` 会杀本脚本拉起的实例，x86 用 `run-split.sh --kill-qemu`。
7. **权限**：部分环境 `sudo`/`apt` 异常时，坚持用用户目录下的 `tools/extract` + `tools/root`，不要强依赖系统安装。
8. **教学内容**（若单独目录/仓）：与 Kernel 进度文档一并 pull，避免课表与路线图脱节。

## 4. 同步后最小自检

```bash
cd ToyKernel
./build.sh                 # x86 完整内核 → ToyImage
./build.sh arm64 && ./run-virt-arm.sh    # 期望：DTB memory… + virt serial shell / mem
./build.sh riscv && ./run-virt-riscv.sh  # 期望：OpenSBI → DTB memory… + serial shell
# TOY_VIRT_MEM=512M ./run-virt-*.sh      # boot/total 应为 0x20000000
./build.sh arm64 BRINGUP=1 && ./run-virt-arm.sh   # hello
./build.sh riscv BRINGUP=1 && ./run-virt-riscv.sh
cd ../ToyImage
./smoke-boot.sh            # 期望 ready / 就绪；含 fork 等路径时再手工 exec FORK.ELF
```

失败时先看：交叉编译器是否在 `PATH`/`tools/extract`、QEMU 是否可执行、是否误用了过期的 `Build/`。

### 家机 RiscV 全量（OpenSBI + QEMU 8.2 / `tools/root`）

- 现象：首启有 `DTB memory base=…`，`[mod] cpu` 后复位环，再入无 DTB（`a0/a1` 未再由 OpenSBI 设置）。
- 根因：OpenSBI 把 CLINT/ACLINT `0x02000000` 划为 M-only（`S/U: ()`）；`HalTimerInit`/`HalTimerPoll` 读 MMIO mtime → S-mode fault。
- 修复：`HAL/RiscV/Hal.c` 改用 `rdtime`（与 Arm64 用 `cntvct` 同思路）。`./run-virt-riscv.sh --headless` 应到 `ToyOS ready`。

## 4.2 正统命令总表与验收

> 命名目标：**自然语序、见字知意**。正统写法不用中横线。  
> 实现见路线图 **PR-C1～C3**；与源码命名整改的合并排期见 [`命名与Shell整改计划.md`](#四shell-命令规划)。

## 0. 命名原则

1. **正统 = 一级词 + 可选二级词**（空格分隔）。例：`tcp listen`，不是 `tcplisten` / `tcp-listen`。
2. **语序**：尽量接近口语/书面祈使句——能「动词在前」就动词在前；网络等成族命令用「对象在前、动作在后」（`tcp listen` = 对 TCP 做 listen），与 `store install` 一致。
3. **用完整单词**：`directory` / `memory` / `database` / `devices`，不用 `dir`/`mem`/`db`/`dev` 当正统（那些只做别名）。
4. **别名**：保留旧粘连名与 Unix 习惯（`ls`、`mkdir`、`tcplisten`），方便熟手；`help` 以正统为主、括号注别名。
5. **无三级**：参数不再充当第三级命令名。
6. **用户别名**：`alias` / `unalias` 可自定义；写入 `TOYOS.DB` 键 `al.<name>`（help 里用户别名带 `*`）。

## 1. 机制（PR-C1）

| 项 | 约定 |
|----|------|
| 分发 | `Argv[0]`=一级；若该一级登记了二级，则 `Argv[1]`=二级，其余为参数 |
| Handler | 二级 Handler 收到的 `Argv[0]`=二级名，参数从 `Argv[1]` 起（已去掉一级） |
| 缺二级 | 打印 `usage: <一级> <子命令…>`（如只打 `tcp`） |
| 别名 | 整词别名（`halt`←`exit`）或粘连别名（`tcp listen`←`tcplisten`） |
| `help` | 按一级分组列出二级；括号列别名 |

```c
ConsoleRegister2("tcp", "listen", "start TCP echo server", Handler);
ConsoleRegisterAliasLine("tcplisten", "tcp", "listen");  /* 旧名 → 正统 */

ConsoleRegister("halt", "stop CPU", Handler);
ConsoleRegisterAlias("halt", "exit");
```

# 五、C 标识符命名规划

> 原 `命名整改.md`。R1～R10、**PR-R-p2** 已归档；未完见 §1.2：**PR-R-riscv64**。

> **本文是清单，不是一次全树 rename。** `HalFrame*` 子集已由 **PR-A15** 落地；**PR-R5** 已落地：`Fs*`→`FileSystem*`、`Init*`→`Initialize*`、`HAL/X64`、`HAL/Virt/`、`gScheduler*`。**`Drv`→`Driver`**（框架文件 / `ToyDriver*` / `TOY_DRIVER_*` / `HalDriverRegister`）已落地。其余仍分 PR / 可穿插。  
> 整改按优先级拆成多个 PR；一次改完会连带炸 [`结构说明.md`](技术手册.md)、[`教学内容/`](../../教学内容/) 函数手册与课堂讲义。  
> 路线图入口：[`路线图.md`](路线图.md) 开头姊妹文档 + **1.3r**（R1～R5 ✅ 柱收官）。

对照：[TianoCore C Coding Standards](https://tianocore-docs.github.io/CodeStyleC/draft/code_style_c.html)（PascalCase、写全英文词、`g` 前缀全局量）。ToyOS **保留** `HAL/` + `Common/{Core,Services,Library}` 分层与自有前缀（`Hal*` / `BOOT_` / `TASK`），但标识符要写全词。

## 1. 原则

| 项 | EDK2 | ToyOS 怎么套 |
|----|------|----------------|
| 文件 / 目录 | PascalCase（`MmcHostDxe.c`、`PciBus.h`） | 已有不少（`Kernel.c`、`FileSystem.c`）；`HAL/X64` ✅ R5；欠账主要在其余缩写文件名 |
| 函数 | PascalCase + **完整英文词**（`InitializeMemory`，不是 `InitMem`） | `KernelMain` / `FileSystemInit` 已接近；`Init*`/`Fs*` ✅ R5；部分 `Hal*` 仍要写全 |
| 全局 | `g` + PascalCase（`gBS`、`gImageHandle`） | `gModules` 形态对；`gSchedulerLock` ✅ R5；其余短名可穿插 |
| 类型 | 常 `EFI_` / `UINTN`；struct 全大写下划线 | ToyOS 可保留 `BOOT_` / `HAL_` / `TASK`，仍 PascalCase 或 `ALL_CAPS` 全词 |
| 宏 | `ALL_CAPS` 单词拼全（合理处） | 见白名单：不要把 `FAT`/`ELF`/`GOP` 写成笑话 |
| 分层 | 包名 / 模块名 | **不要**把 `HAL/` 收进 `Common/`，也不要把 `Hal*` 改成无前缀 |

**已接近目标、优先不要动**（除非同 PR 顺手）：`KernelMain`、`SchedulerCreate`、`VirtualMemorySpaceClone`、`PhysicalMemoryInit`、`FileSystemInit`、`HalSerialWrite`、`HalVideoFillRect`、`BootInfoGet`。

# 六、应用商店规划（历史，1.3s/m 已收官）

## 1. 目标（用户原话对齐）

- 能浏览可安装项（程序 ELF、可选「驱动包」）  
- 能下载并落到系统卷（`TOYOS:`）  
- 驱动与应用分栏；失败可回滚/提示  

**非目标（明确不做或远后置）**：账号体系、付费、沙箱签名 PKI 全家桶、后台自动更新守护进程。

---

## 2. 依赖与现状

| 依赖 | 现状 |
|------|------|
| 网络 | virtio-net / e1000（**H4 ✅**）；用户态 socket 需 `LWIP=1` |
| 文件系统 | VFS + FAT ✅；写文件 ✅（FS3） |
| 包格式 | **S0 ✅** 约定；**S1 ✅** Shell 安装到 `Apps/` |
| 驱动热加载 | **无**——今日驱动是内核链接 + `ToyDriverRegister` |

因此：**第一期应用商店只装用户态 ELF（与主题/资源）**；「下载驱动」若指内核 `.ko` 式热插拔，须先有加载器——建议二期。

---

## 3. 分阶段

### 期 0 — 文档与目录约定（**PR-S0 ✅**）

Guest（`TOYOS:`）布局：

```text
Apps/                     # 已安装 ELF（可写；S0 空占位）
Store/                    # 本地/下载缓存（可写；S0 空占位）
Assets/Store/
  README.md               # 字段说明
  catalog.txt             # 离线目录样本
  packages/<id>/          # 可选 PKG.TXT + 载荷（S1）
```

仓库源：`ToyKernel/Apps/`、`Store/`、`Assets/Store/`；由 `prepare-rootfs` / `prepare-virt-rootfs` 同步进镜像。

### 期 1 — 「本地商店 / 优盘商店」（**PR-S1 ✅**）

- Shell：`store list` / `store install <id>` → 复制到 `Apps/`  
- 载荷：`Store/`、卷根、或 `Assets/Store/packages/<id>/`  
- 验收：无网 `store install hello` 后 `Apps/HELLO.ELF` 可 `exec`  

### 期 2 — 联网下载（**PR-S2 ✅**）

- 内核 `StoreNet.c`：内建 TCP 客户端 + **HTTP/1.0 GET**（无需 lwIP）  
- Shell：`store sync` / `store fetch <id>` / `store repo [ip:port]`  
- 仓库：宿主 `python3 -m http.server 8080`；Guest 默认 `10.0.2.2:8080`（`ToyDB store.repo=`）  
- 落盘：`Store/catalog.txt`、`Store/<file>`，再 `store install`（S1）  
- 校验：`sha256=-` 跳过；**8 位 hex** = 教学 **FNV-1a-32**（非真 SHA-256）  
- 演示树：`ToyImage/store-repo/`  

### 期 3 — 「驱动包」（**PR-S3 ✅**）

| 档 | 含义 | 难度 |
|----|------|------|

## 【归档】PR-P4：简单信号 ✅
