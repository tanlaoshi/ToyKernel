# ToyKernel 命名整改清单（EDK2 风格）

> **本文是清单，不是一次全树 rename。** `HalFrame*` 子集已由 **PR-A15** 落地；其余仍分 PR。  
> 整改按优先级拆成多个 PR；一次改完会连带炸 [`结构说明.md`](结构说明.md)、[`教学内容/`](../../教学内容/) 函数手册与课堂讲义。  
> 路线图入口：[`路线图.md`](路线图.md) 开头姊妹文档 + **1.3r PR-R5**（首批）；剩余项仍可穿插。

对照：[TianoCore C Coding Standards](https://tianocore-docs.github.io/CodeStyleC/draft/code_style_c.html)（PascalCase、写全英文词、`g` 前缀全局量）。ToyOS **保留** `HAL/` + `Common/{Core,Services,Library}` 分层与自有前缀（`Hal*` / `BOOT_` / `TASK`），但标识符要写全词。

---

## 1. 原则

| 项 | EDK2 | ToyOS 怎么套 |
|----|------|----------------|
| 文件 / 目录 | PascalCase（`MmcHostDxe.c`、`PciBus.h`） | 已有不少（`Kernel.c`、`FileSystem.c`）；欠账主要在缩写文件名与 `HAL/X86_64` |
| 函数 | PascalCase + **完整英文词**（`InitializeMemory`，不是 `InitMem`） | `KernelMain` / `FileSystemInit` 已接近；`Init*` / `Fs*` / 部分 `Hal*` 要写全 |
| 全局 | `g` + PascalCase（`gBS`、`gImageHandle`） | `gModules` 形态对；`gSchedLock`、`gRrHome` 等词没写全 |
| 类型 | 常 `EFI_` / `UINTN`；struct 全大写下划线 | ToyOS 可保留 `BOOT_` / `HAL_` / `TASK`，仍 PascalCase 或 `ALL_CAPS` 全词 |
| 宏 | `ALL_CAPS` 单词拼全（合理处） | 见白名单：不要把 `FAT`/`ELF`/`GOP` 写成笑话 |
| 分层 | 包名 / 模块名 | **不要**把 `HAL/` 收进 `Common/`，也不要把 `Hal*` 改成无前缀 |

**已接近目标、优先不要动**（除非同 PR 顺手）：`KernelMain`、`SchedulerCreate`、`VirtualMemorySpaceClone`、`PhysicalMemoryInit`、`FileSystemInit`、`HalSerialWrite`、`HalVideoFillRect`、`BootInfoGet`。

## 2. 现存 → 建议（抽样，不是每一个 `.o`）

### 2.1 目录 / 文件

| 优先级 | 现存 | 建议 | 备注 |
|--------|------|------|------|
| P0 | `HAL/X86_64/` | `HAL/X64/` | EDK2 目录名是 `X64`；牵动 Makefile、`link.ld`、文档 |
| P1 | `HAL/RiscV/` | `HAL/RiscV64/` | 可选；与 `Arm64` 并列时再定 |
| P1 | `HAL/<Arch>/Page.c` | `PageTable.c` | `Page` 太短，且与「一页内存」易混 |
| P1 | `HAL/X86_64/Isr.S`（若仍用此名） | `Interrupt.S` | ISR 非白名单；EDK2 常用 Interrupt |
| P1 | `HAL/<Arch>/VirtioBlk.c` `.h` | `VirtioBlock.c` `.h` | `Blk` 未写全；协议名 virtio-blk 可留注释 |
| P2 | `HAL/X86_64/SmpBoot.c` | `SmpBoot.c` 可留，或 `MultiprocessorBoot.c` | `Smp` 见白名单；若写全则整族 `HalSmp*` 一起改 |
| P2 | `HAL/<Arch>/StubHelloBlob.c` | `HelloBlob.c` | 去掉 `Stub` 或改 `BringupHelloBlob.c` |
| P2 | `User/brkdemo.c` 等 | `BrkDemo.c` / `ExecDemo.c` / `PipeDemo.c` | 用户程序源文件；产物仍受 FAT 8.3 约束（见 P3） |
| P2 | `User/include/toy_syscall.h` | `ToySyscall.h` | snake_case → PascalCase |
| P3 | `User/crt/crt0.S`、`unistd.c` | **保持** | Unix CRT 惯例，不要 EDK2 化 |
| P3 | `link.ld`、`build.sh` | **保持 kebab/小写** | 见 2.6 |

`Common/Core`、`Common/Services`、`Common/Library`、`Include/*.h` 多数已是 PascalCase（`KernelModules.c`、`VirtualMemory.h`），**不必为改而改**。没有独立的 `InitMem.c` 一类文件——`Init*` 全在 `KernelModules.c` 里。

### 2.2 模块名（`gModules[]` 字符串）

日志里是 `[mod] mem` 这类短名。改字符串等于改课堂观察点，建议 **P1 与 `Init*` 同 PR**，并改讲义。

| 现存 | 建议 | 对应 Init |
|------|------|-----------|
| `"serial"` | `"serial"` 可留 | `InitSerial` |
| `"mem"` | `"memory"` | `InitMem` |
| `"vmm"` | `"virtual-memory"` 或 `"VirtualMemory"` | `InitVmm` |
| `"fs"` | `"file-system"` | `InitFileSystemModule` |
| `"sched"` | `"scheduler"` | `InitSched` |
| `"net"` | `"network"`（可选） | `InitNetModule` |
| `"smp"` / `"cpu"` / `"gui"` / `"usb"` / `"video"` / `"console"` | 可留 | 白名单或已是全词 |

### 2.5 脚本（次要）

EDK2 的 `build.sh`、`Run*.sh` 混用；**Unix 脚本继续 kebab-case 是合理的**。C 标识符才是主债。

| 现存 | 建议 |
|------|------|
| `run-virt-arm.sh` | **保持**；不要改成 `RunVirtArm.sh`（除非全仓库脚本统一 PascalCase，不推荐） |
| `run-virt-riscv.sh` / `run-virt-common.sh` / `smoke-virt.sh` | **保持** |
| `prepare-virt-rootfs.sh` / `build.sh` | **保持** |
| 环境变量 `TOY_VIRT_*` | 可留；文档写全含义即可 |

### 2.6 用户 ELF 文件名

`HELLO.ELF`、`CAT.ELF`、`PIPEDEMO.ELF` 受 **FAT 8.3 + 课堂大写** 约束，**不要**改成 `Hello.elf`。源文件 PascalCase（`BrkDemo.c`）与盘上 8.3 名可以不同，Makefile 里写明映射。

## 3. 优先级

| 级 | 范围 | 建议切法 |
|----|------|----------|
| **P0** | `Include/*.h` 与 `Hal*` 公开 API | 单独 PR：门面改名 + 三 arch 实现一起过 `./build.sh` 与 `smoke-boot.sh` |
| **P1** | Common 导出（`Fs*`、`Theme*Bg`、模块表字符串、`gSched*`） | 按子系统：FS 一刀、模块表+Init 一刀、Theme 一刀 |
| **P2** | `static` 内部、`CommandMem`、`MemCopy`、Gui 短名 | 可跟功能 PR 顺手，不必单开 |
| **P3** | 脚本 kebab、CRT、`HELLO.ELF` | 默认不动 |

`HAL/X64` 目录改名与 `HalCpuId` 等 API 改名不要塞进同一个 PR。

## 4. 缩写白名单（不要写全成笑话）

下列 **保持**，不要改成右边那种：

| 保持 | 不要写成 |
|------|----------|
| `FAT` | `FileAllocationTable` |
| `ELF` | `ExecutableAndLinkableFormat` |
| `GOP` | `GraphicsOutputProtocol`（x86 Boot 语境保留 GOP） |
| `ATA` | `AdvancedTechnologyAttachment` |
| `ACPI` / `MADT` | 展开全称 |
| `PCI` / `PCIe` | |
| `USB` / `XHCI` | |
| `GPT` | `GuidPartitionTable` 作类型名尚可，宏前缀保持 `GPT_` |
| `IRQ` / `Irq` | `InterruptRequest` |
| `IO` / `Io` / `MMIO` / `Mmio` | `MemoryMappedInputOutput` |
| `CPU` / `Cpu` | `CentralProcessingUnit` |
| `BSP` / `AP`（SMP 语境） | 可选用全称，但不要强制 |
| `EOI` / `Eoi` | 建议保持 |
| `TLB` / `Tlb` | |
| `PTE`（页表项宏里） | `PageTableEntry` 嵌进每个宏 |
| `COW` 作注释 | 标识符用 `CopyOnWrite`；注释可写 COW |
| `DTB` / `Dtb` / `FDT` | Device Tree 专有 |
| `ELF` 重定位 `R_*` / `PT_*` / `DT_*` | System V ABI 字面量 |
| `GIC` / `PLIC` / `LAPIC` / `IOAPIC` | 硬件名 |
| `UART` / `COM1` / `PL011` | |
| `DMA` / `BAR` / `MSI` | |
| `CRC` / `GUID` / `UUID` | |
| `lwIP` / `Lwip` | 第三方专有名词 |
| `HAL` / `Hal` | 分层专有名词 |
| `SMP` / `Smp` | 可留；若写全则整族一起 |
| `EDID` / `RSDP` | 规范缩写 |
| `POSIX` 出现在注释 | 不要当标识符展开 |

参数名 `Buf`/`Len`/`Ctx`/`Idx` 允许短名（EDK2 也大量 `Buffer`/`Length`，但局部 `Len` 可接受）。**新代码**对外 API 优先 `Buffer`/`Length`/`Context`/`Index`。

## 5. 执行约定

1. **HalFrame 门面子集已由 PR-A15 落地**；其余条目仍只列清单，未改 `.c`/`.h`。
2. 每个 rename PR：编译三 arch、`smoke-boot.sh`、相关 `run-virt-*.sh --headless`；同步改 `结构说明` / 教学内容里出现的符号。
3. 不要在同一 PR 里既改行为又大规模改名。
4. 新代码按本文原则命名，避免再堆 `InitMem` / `GetBlk`。
