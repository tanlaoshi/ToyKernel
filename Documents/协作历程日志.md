## 0. 一句话读完

你从「办公室接上家里未同步的 Image/Boot」起步，一路把 ToyOS 从「能进内核的实验盘」，做成：

**UEFI 引导 + FAT 系统盘 + 教学桌面 + 用户态进程 + 网络 + 跨架构 virt + 商店/Files + 可协作的路线图机制（JX/TG）**。

过程里反复出现的主旋律是：**先能跑 → 再解耦 → 再产品感（GUI/Settings）→ 再跨架构 → 再命令与命名的「见字知意」**。

## 2. 阶段编年（按能力跃迁）

### 阶段 A — 接续与能跑（会话起点）

**你问什么**

- 家里写了很多，办公室怎么继续？Kernel 有 GitHub，Image/Boot 没同步。
- `guest has not initialized`、只停在 Boot、磁盘空间告警。

**发生了什么**

- 办公室侧改 `run.sh` / NVRAM / 镜像同步，把「能进 Kernel」重新立住。
- 埋下长期主题：**三仓协同（ToyKernel / ToyBoot / ToyImage）** 与双机同步债。

**可分析的习惯**：先救现场，再谈架构；同步问题会反复出现，后来催生了路线图里的「同步说明」与 TG。

---

### 阶段 B — 命名意识觉醒

**你问什么**

- Kernel 应按 EDK2：单词写全，UI 等通用缩写可留；先出方案再改。

**发生了什么**

- 命名债被正式立项（后来并入路线图「五、C 标识符命名规划」与 R1～R5 / R6+）。
- 同期探网络：`ping 10.0.2.2`（QEMU user 网）；弄清「换宿主网络仍 ping 这个」的课堂语义。

**可分析的习惯**：标准感来自 EDK2 经验；愿意「先方案后动刀」，避免一次全树 rename。

---

### 阶段 C — 窗口与显示体感

**你问什么**

- QEMU 窗相对 1920×1200 过小/过大；点阵能否上 TTF；放大点阵字。
- 放弃 NVMe/核显幻想，**按路线图自然下一步**；开窗拖动。

**发生了什么**

- 分辨率 / 缩放 / Terminus 等体感迭代。
- **窗口拖动** 进入长迭代：内容消失 → 残留重叠 → 拖不动 → 拖影 → 闪屏 → 合成/脏 Present 逐步收口（G 族）。
- Boot 侧「真机问最佳分辨率」的愿望提出；QEMU 仍走脚本 edid + `THEME.CFG`。

**可分析的习惯**：GUI 是你最愿意「多轮验证」的子系统；路线图纪律开始压过「硬件冲动」。

---

### 阶段 D — 安装哲学 → 落回 FAT

**你问什么**

- 装到硬盘、NVMe/SATA、与 Windows/Linux 共存、GRUB chainload、Kernel 是否必须在 ESP。
- Bootmgr/NTFS vs Linux；FAT 4GB 限制是否可接受。

**你自己的收束**

> 「先不做那么复杂，用 FAT 至少能跑。Kernel 要能读 FAT，还要有程序加载器。」  
> 并要求：**加强的 FAT 不只 QEMU 有用**；QEMU 加 FAT 盘验证。

**发生了什么**

- Block + GPT + FAT、`TOYOS.ID`、双盘（ESP + rootfs）产品路径成形。
- 只读 → 写入 → 子目录/删除 → LFN → Files 浏览器；用户 ELF（`WRITE`/`CAT` 等）。

**可分析的习惯**：真机愿景很强，但能主动降维到可交付切片；「课堂可演示」优先于「完整安装器」。

---

### 阶段 E — Common/HAL 解耦与目录重构

**你问什么**

- Common 是否真通用？端口 I/O 仍在 Common 能否改善？`int 0x80` 是否过时？
- 要求按 Blocks 指南给**执行计划先不改码**；再改成 **drivers 进各 arch 的 HAL**；分 4 个 PR。
- `Kernel.c` 太重；`BOOT_CONFIG` 绑死 RISC-V 等；PascalCase 目录名（`Common`/`HAL`/`Include`）。

**发生了什么**

- PR-1～4 类：分层搬迁、Boot 解耦（`BOOT_INFO`）、HAL 门面、帧类型脱钩等。
- 同步文档 / README / 路线图开始成为「第二工作面」。

**可分析的习惯**：架构问题先要「评估方案」；实现坚持渐进 PR；命名风格与目录风格一并推行。

---

### 阶段 F — 桌面产品化（D1～D7 + Theme/DB）

**你问什么**

- Settings 改分辨率；桌面图标双击；主题持久化；闪屏 code review 入路线图。
- Caps/LED；焦点点桌面是否应失焦窗（先讨论再改码）。

**发生了什么**

- Theme + `THEME.CFG` + `TOYOS.DB`；Settings；Files；字体/壁纸/图标资源树。
- 分辨率「写盘 → 退出 QEMU → 重跑脚本」成为课堂真相（Guest reboot 不改宿主 edid）。

**可分析的习惯**：交互语义会先问清楚；验证条目很具体（「标题栏灰」「叉号居中」）。

---

### 阶段 G — 网络加深与用户态「像进程」

**你问什么**

- TCP 重传/窗口；`tcplisten` 提示符与 Ctrl+C；再嵌 lwIP。
- COW fork、`WNOHANG`、动态库 `.so`；后来说要 `syscall`/`sysret`，`int 0x80` 留作 legacy 教学。

**发生了什么**

- builtin TCP/UDP 可用；lwIP 可选；进程/内存演示 ELF 变多。
- Shell 挂起命令与提示符交互成为长期边角（直到 C1 前后仍在修 `tcp listen`）。

**可分析的习惯**：网络与进程都走「能演示 → 再加深」；教学双路径（legacy + 现代入口）意识明确。

---

### 阶段 H — 跨架构 virt 与课堂双路径

**你问什么**

- Arm64/RiscV 冒烟；Build 目录要与源码分层同构；「以后是不是不在 ToyImage 跑了？」
- 壁纸/开始菜单/用户态 GUI 库（命名必须 `libToy*`）；商店 / Files 侧栏 / 模块包。

**发生了什么**

- virt：ramfb + virtio-input/blk/net + 同一套 Common Gui；`smoke-virt`。
- **产品主路径仍是 x86 + ToyImage + OVMF**；virt 是第二课堂。
- 柱状推进：L / F / R / U / S / M / V1～V2 等（路线图文末归档可对照）。

**可分析的习惯**：接受「两条启动故事」；同步文档（家↔公司、工具链）成为一等需求。

---

### 阶段 I — 文档收敛与协作制度化（近端）

**你问什么**

- 文档整合为三件套：README / 路线图 / 技术手册；空壳删掉。
- Shell **全词 + 一级/二级 + 别名**（不要中横线）；再要用户自定义 `alias`。
- 明确暗号：**JX** = 下一刀且不擅自提交；**TG** = 验证后同步提交。
- 分辨率偏好被 stash/cwd 盖掉（1280→1600）；收 D-res。
- **本篇**：把对话做成历程日志，供你分析。

**发生了什么**

- 活文档只留三份正文（+ 本历程日志）。
- Shell：C1 分发 → C2 改挂 → C3 store + 用户 `alias`/`unalias`（`al.*`→DB）。
- D-res：rootfs THEME 权威、stash 不回盖、默认 1280×720、virt 种子对齐、CFG `mode=` 覆盖 DB。

**可分析的习惯**：协作从「聊天驱动」升级为「暗号 + 指针表驱动」；你开始有意识地**复盘过程本身**。

## 3. 能力地图：对话里长出来的 ToyOS

```text
同步能跑
  → 命名/分层意识
  → GUI 体感（拖动/合成/主题）
  → 安装愿景收束到 FAT 系统盘
  → Common/HAL/Boot 解耦 + 多 PR
  → Settings/Files/DB/Theme
  → 网络 + 用户态进程/ syscall
  → Arm64/RiscV virt 第二路径
  → 商店 / 侧栏 / 模块包
  → Shell 全词+别名 + 文档三件套 + JX/TG
  → 分辨率偏好稳健（D-res）
```

## 4. 你的决策模式（便于自我分析）

| 模式 | 表现 | 例子 |
|------|------|------|
| **愿景拉满，切片落地** | 先问双系统/NTFS/NVMe，再主动选 FAT | 阶段 D |
| **验证门禁** | 「通过再提交」；具体失败现象贴终端 | GUI 多轮、tcp listen |
| **计划先于代码** | 「先执行计划别改码」；PR 拆分 | HAL 重构、命名整改 |
| **路线图权威** | 「按路线图自然下一步」；后期 JX | 放弃核显冲动 |
| **标准感** | EDK2 全词、目录 PascalCase、`libToy*` | 命名轨 / GUI 库 |
| **双机意识** | 同步文档、TJTS/TG、三仓 push | 全程 |
| **教学双轨** | `int 0x80` 保留 + `syscall`；x86 主路径 + virt | 阶段 G/H |
| **交互先辩语义** | 「点桌面该不该失焦？先回答别动代码」 | 焦点讨论 |

若你要给自己打标签：更像 **产品向的教学 OS 作者**，而不是「只堆 syscall 的内核课作业」。

## 5. 反复出现的痛点簇（下次可预警）

1. **GUI 合成**：拖影 / 闪屏 / 关窗残留 / 焦点与 Z 序 — 占对话比重最大之一。  
2. **提示符与挂起命令**：`tcp listen`、exec 后换行、滚轮滚动丢色 — Shell UX 债。  
3. **主题与分辨率权威**：cwd / stash / rootfs / DB / CFG 多源 — 催生 D-res。  
4. **双机与三仓**：只推 Kernel 不够；Image/Boot/NVRAM/THEME 易漂。  
5. **命名债两轨混谈**：Shell 用户字符串 vs C 标识符 — 后来被刻意拆开（甲轨 / 乙轨）。
