## 1. Driver.h 结构体

### TOY_DRIVER

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `Name` | `const char *` | 驱动名；`lsdev` 打印用；注册时必填 |
| `Class` | `TOY_DRIVER_CLASS` | `NONE` / `BLOCK` / `INPUT` / `NET` / `DISPLAY`；`ProbeClass` 过滤用。`DISPLAY` 枚举已有，当前无注册驱动 |
| `Match` | `const void *` | 注释写「PCI/virtio/DTB 匹配表占位」；**现网全部为 `NULL`**，匹配写在 `Probe` 里。标准化柱（D-tpl）**不实现**表驱动匹配，Match **继续占位** |
| `Probe` | `int (*)(const TOY_DRIVER *Self, void *BusCtx, void **OutPriv)` | 有设备返回 `0`，可选写 `*OutPriv`；无设备非 0。框架恒传 `BusCtx=0` |
| `Bind` | `int (*)(TOY_DRIVER_INSTANCE *Inst)` | Probe 成功后调用；挂类 Backend（Input/Block/Net）。可为 NULL（少见） |
| `Remove` | `void (*)(TOY_DRIVER_INSTANCE *Inst)` | 解绑/失败回滚/RemoveAll；可选 |

上限：`TOY_DRIVER_MAX_DRIVERS` = 16，`TOY_DRIVER_MAX_INSTANCES` = 16。

### TOY_DRIVER_INSTANCE

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `Driver` | `const TOY_DRIVER *` | 指向已注册描述符 |
| `Priv` | `void *` | Probe 写出的私有上下文（多数驱动不用） |
| `Bound` | `int` | Bind 成功后置 1；`lsdev` 只列 Bound 实例 |

## 2. 核心 API

### ToyDriverRegister

- **签名**：`int ToyDriverRegister(const TOY_DRIVER *Driver);`
- **语义**：校验 `Name`+`Probe`，追加到 `gDrivers[]`；表满返回 -1。
- **何时**：各 `*DriverRegister()` / `*Register()` 内，由 `HalDriverRegister()` 统一拉起。**只登记，不 Probe。**

### ToyDriverProbeAll

- **签名**：`int ToyDriverProbeAll(void);`
- **语义**：等价 `ToyDriverProbeClass(TOY_DRIVER_CLASS_NONE)`，Probe 全部已注册驱动。
- **何时**：一般不直接当主路径；启动用按类 Probe。

### ToyDriverProbeClass

- **签名**：`int ToyDriverProbeClass(TOY_DRIVER_CLASS Class);`
- **语义**：
  1. 遍历已注册驱动；`Class!=NONE` 时跳过其它类
  2. 已 Bound 的跳过
  3. `Probe(D, 0, &Priv)==0` 才继续
  4. 占实例槽 → 调 `Bind`；Bind 失败则 `Remove` 并丢弃槽
  5. 成功：`Bound=1`，串口 `driver: registered=N bound=M (+K)`
- **何时**：`InitializeDriver` 早期只 Probe **BLOCK**（避免 VMM 前摸死 8042）；之后 `HalBlockInit` / Input / Net 初始化再按类 Probe。

## 3. 设备类 Backend

### INPUT_BACKEND（`DriverInput.h`）

| 字段 | 必填 | 作用 |
| --- | --- | --- |
| `Poll` | 是 | 排空硬件/事件进队列 |
| `KeyboardDequeue` | 是 | 取键盘报告 |
| `KeyboardSetLeds` | 否（可 NULL） | LED；NULL 时 Hal 返回 -1 |
| `MousePresent` | 是 | 是否有鼠标 |
| `MouseDequeue` | 是 | 取鼠标报告 |

`ToyDriverInputAttach`：挂**全局唯一** Backend；后 Attach 覆盖前者。

### BLOCK_BACKEND（定义在 `Block.h`，经 `ToyDriverBlockAttach`）

| 字段 | 必填 | 作用 |
| --- | --- | --- |
| `Probe` | 是 | 盘号是否存在 |
| `ReadSectors` / `WriteSectors` | 是 | 512B 扇区读写 |
| `Flush` | 否 | 刷写；NULL=空成功 |

Attach → `BlockRegisterBackend`；多 Block 驱动可各自 Bound，**后端指针后挂覆盖**（注释意图：NVMe > AHCI > ATA）。

### NET_BACKEND（`DriverNet.h`）

| 字段 | 作用 |
| --- | --- |
| `Ready` / `Poll` | 就绪与收发包轮询 |
| `GetMac` / `GetIp` / `FormatIp` / `ParseIp` | 地址 |
| `Ping` / `GetStats` | 诊断 |
| `SendIp` / `Checksum` / `SetLwIpRx` | 发包与 lwIP 收包开关 |

全部由 Attach 校验为非 NULL。同样**单槽全局**，后 Bind 可盖掉先 Bind（如 e1000 盖 virtio-net）。

**重要**：`Poll` / `Irq` **不是** `TOY_DRIVER` 上的钩子；轮询在 Backend，中断在 HAL/驱动私有（如 `XhciIrq`）。

## 4. 现有驱动实现模式

### 最简单：`ps2-kbd`（`HAL/X64/Drivers/InputPs2.c`）

| 钩子 | 做什么 |
| --- | --- |
| Probe | 若 Input 已被 xhci 占用则失败；需 VMM；`Ps2InitHw`（i8042 `0x60/0x64` 自检） |
| Bind | `ToyDriverInputAttach(&gPs2Backend)` |
| Remove | `gPs2Ready=0` |
| Poll | Backend：排空状态口，解析 Set2 → HID |
| Irq | 无；纯 Poll |

### 最复杂（框架侧）：`xhci-hid`（`InputXhci.c`；`XhciDevice.c` 是枚举库不是 TOY_DRIVER）

| 钩子 | 做什么 |
| --- | --- |
| Probe | PCI 扫 USB(class `0x0C03`)，ProgIF=`0x30`；映射 BAR；`XhciInit`；要有 HID 键或鼠才算成功；真机可换控制器重试 |
| Bind | `ToyDriverInputAttach` |
| Remove | `gXhciReady=0` |
| Poll | `XhciDrainEvents` |
| Irq | 另路 `InputXhciArmIrq` → `XhciIrq`（非框架字段） |

### 规划中的课堂 Demo（PR-D-tpl-2，非现网）

| 钩子 | 规格（设计稿） |
| --- | --- |
| Name / Class | `demo-driver` / `INPUT` |
| Probe | 恒 0；串口 `demo: probe called` |
| Bind | **永不** `ToyDriverInputAttach`；只占实例槽；串口 `demo: bind called` |
| 目的 | `lsdev` 固定可见，且不抢 xhci/ps2 的 Input Backend |

真驱动仍必须在 Bind 里 Attach 才会真正驱动硬件；Demo 是故意的例外。

## 5. 驱动注册链

```
Kernel 模块 `driver`
  → HalDriverRegister()          # HAL/X64/HalDevices.c：只 Register
       Ahci / Ata / Nvme / Msc / InputXhci / InputPs2 / Net / E1000
       （D-tpl-2 起：可选 DemoDriverRegister，TOY_DEMO_DRIVER 默认 1）
  → ToyDriverProbeClass(BLOCK)   # 早期块设备

（分页/VMM 起来后）
  → HalBlockInit / Input*Init / NetInit
  → 再 ToyDriverProbeClass(INPUT|NET|BLOCK…)
```

Arm64/RiscV：`HalDriverRegister` 只挂 virtio-blk / virtio-input / virtio-net（RiscV 可受 Board 能力宏裁剪）。本标准化柱模板目录只落 **X64**。

## 6. 驱动匹配模式

| 驱动 | Name | Probe 如何匹配 |
| --- | --- | --- |
| ahci | `ahci` | PCI class `0x010601`，BAR5 |
| nvme | `nvme` | PCI class `0x010802`，BAR0 |
| ata-pio | `ata-pio` | 固定 I/O `0x1F0` |
| usb-msc | `usb-msc` | 软条件（VMM）；Bind 可不挂 Block |
| e1000/e1000e | `e1000*` | PCI VID `0x8086` + DID 表 |
| virtio-net-pci | `virtio-net-pci` | PCI `1AF4:1000` |
| ps2-kbd | `ps2-kbd` | 固定 8042 +「Input 尚未 Ready」 |
| xhci-hid | `xhci-hid` | PCI USB + ProgIF 0x30 + HID 枚举成功 |
| virtio-* (virt) | `virtio-blk/input/net` | **固定 MMIO 窗扫描**（非 DTB） |

**本树无 DTB `compatible` 匹配实现。** `TOY_DRIVER.Match` 从未使用；三模式见 [`驱动匹配规范.md`](../驱动匹配规范.md)，**不**改成真表驱动。

`lsdev`（`ShellCmdSystem.c`）：只列 **Bound** 实例 → `  <Name>  <block|input|net|…>`；网卡可附带 link 信息。因此「只 Register、Probe 失败、或 Bind 失败」都不会出现在 `lsdev`。Demo 靠 Probe=0 + Bind=0（不 Attach）进入 Bound 列表。

## 7. 新人容易卡住的点

1. **Register ≠ 上线**：只 `ToyDriverRegister` 不够；还要某次 `ToyDriverProbeClass`，且 `Probe`/`Bind` 都返回 0，`lsdev` 才看得见。
2. **`Match` 是空的**：头文件看起来有匹配表，实际全靠自己在 Probe 里扫 PCI/口/MMIO；无模板可抄时只能读真驱动（D-tpl-1 起可拷 `_template/`）。
3. **单槽 Backend**：Input/Net（及 Block 后端指针）后挂覆盖前挂；顺序与「谁先 Ready」强相关（xhci vs ps2、virtio vs e1000）。课堂 Demo **故意不 Attach**，避免踩此坑。
4. **Probe 时机 / VMM**：许多驱动要求分页已开；过早 Probe 会失败或踩硬件。
5. **Makefile 只通配一层**：`Drivers/*.c` 与 `Drivers/XHCI/*.c`；`Drivers/_template/Template.c` **不会**自动进编译（且**禁止**把 `_template` 加进通配）。扁平 `Drivers/DemoDriver.c` **会**编入。子目录 `Drivers/DemoDriver/Foo.c` 不会。
6. **Poll/Irq 不在 TOY_DRIVER 上**：新人找「框架 Poll 钩子」会落空，要填 Backend 或自接中断。
7. **验收勿用裸 `grep template`**：D-tpl-1 用设计稿 §1.2 的**精确符号** `nm`；二进制里偶然子串不作为硬失败。
