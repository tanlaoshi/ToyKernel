## 0. 目标与硬约束

| 项 | 结论 |
| --- | --- |
| 目标 | 新人能按 **5 步**从模板拷出可 `lsdev` 的 INPUT 驱动；不改现有 Driver* API / 真驱动行为 |
| 模板目录 | `HAL/X64/Drivers/_template/` |
| **模板永不进 Kernel** | `_template/**/*.c` **禁止**出现在 `DRIVER_SRCS`；硬验收用**精确符号** `nm`（见 §1.2），不得出现模板定义的符号 |
| Demo | 扁平 `HAL/X64/Drivers/DemoDriver.c`（走现有 `Drivers/*.c` 通配）；**默认注册**；Bind **永不** `ToyDriverInputAttach` |
| Demo 开关 | `TOY_DEMO_DRIVER` 默认 **1**（`#ifndef` 保护）；`-DTOY_DEMO_DRIVER=0` 关闭 |
| Match | 模板与 Demo 均 `Match = NULL`；匹配写在 `Probe`（与现状一致） |
| 类选择 | 模板骨架与 Demo 用 **`TOY_DRIVER_CLASS_INPUT`**（Backend 字段最少、可对照 `ps2-kbd`） |

**不做（本柱）**：改写真驱动填 Match；框架级 PCI/DTB 自动分发；可加载模块；改 API 签名。

## 1. 目录与构建

### 1.1 落盘（PR-D-tpl-1）

```text
HAL/X64/Drivers/
  _template/                 # 只作拷贝源；永不链接
    README.md                # 30～50 行：5 步开篇（见 §2 末 / 优化 1）
    Template.c               # TOY_DRIVER + INPUT_BACKEND 骨架
  DemoDriver.c               # PR-D-tpl-2：课堂 Demo（自动编入）
  InputPs2.c / …             # 既有真驱动（不动）
```

可选（同一刀或指南刀）：`_template/Template.h` **不要**。注册入口用 `void TemplateDriverRegister(void);` 写在 `.c` 内即可；新人复制后改名。

### 1.2 Makefile 规则（PR-D-tpl-1 验收写死）

当前（保持）：

```make
DRIVER_SRCS   := $(wildcard HAL/$(HAL_ARCH)/Drivers/*.c)
XHCI_SPLIT_SRCS := $(wildcard HAL/$(HAL_ARCH)/Drivers/XHCI/*.c)
DRIVER_SRCS   += $(XHCI_SPLIT_SRCS)
```

- **一层** `Drivers/*.c`：不会扫到 `_template/Template.c` → 模板天然不进链接。  
- **禁止**改成 `Drivers/**/*.c` 或把 `_template` 加入列表。  

**硬验收（精确符号，勿用裸 `grep -i template`）**：`./build.sh` 后执行：

```bash
nm Build/HAL/X64/Kernel.elf | grep -iE \
  'TemplateDriver|gTemplate|TemplateProbe|TemplateBind|TemplatePoll|TemplateKbdDequeue|TemplateMousePresent|TemplateMouseDequeue|TemplateRemove'
```

预期输出：**空**（无任何匹配）。

说明：裸 `grep -i template` 或对 ELF 二进制 `grep template` 可能因无关子串误报，**不作为硬失败条件**（可选参考）。

**符号命名约定**（`_template/Template.c`）：

- 所有函数：`Template*` 前缀  
- 所有静态变量 / 静态对象：`gTemplate*` 前缀  
- 不要用无前缀的 `template` 作普通标识符（降低误报）

Arm64/RiscV：本柱 **只做 X64 模板目录**；virt 板继续各自 `HalDriverRegister`。指南中注明「其它 arch 可仿照拷一份」。

## 2. 模板 `Template.c` 设计（拷贝源）

### 2.1 职责

最小可复制的 **INPUT** 驱动骨架：

1. 填 `TOY_DRIVER`（Name / Class / Probe / Bind / Remove）  
2. 填 `INPUT_BACKEND`（可先空转）  
3. 暴露 `TemplateDriverRegister()` → `ToyDriverRegister`  
4. 注释标明：复制后改名、放到 `Drivers/*.c`、在 `HalDriverRegister` 加一行

### 2.2 建议行为（模板默认）

| 钩子 | 模板默认 | 说明 |
| --- | --- | --- |
| `Probe` | 返回 **`-1`** | 故意不上线；避免误链时抢 Input 槽。注释：`/* TODO: 发现设备则 return 0 */` |
| `Bind` | `ToyDriverInputAttach(&gTemplateBackend)` | 仅当 Probe 成功才会走到（**真驱动**路径；Demo 另见 §3） |
| `Remove` | 清 `gTemplateReady=0` | 与 ps2 同模式 |
| Backend `Poll` | 空函数 | |
| `KeyboardDequeue` / `MouseDequeue` | 返回 0（无事件） | |
| `MousePresent` | 返回 0 | |
| `KeyboardSetLeds` | `NULL` | 允许 |

**Name 字符串**：模板内用 `"template-input"`（仅源码；不进 Kernel）。新人改为自己的名字。

### 2.3 伪代码骨架（实现刀照抄展开）

```c
/* _template/Template.c — 拷贝源；勿加入 DRIVER_SRCS */
#include "Driver.h"
#include "DriverInput.h"

static int gTemplateReady;

static void TemplatePoll(void) { }

static int TemplateKbdDequeue(HAL_KEYBOARD_REPORT *R) {
    (void)R;
    return 0;
}

static int TemplateMousePresent(void) { return 0; }

static int TemplateMouseDequeue(HAL_MOUSE_REPORT *R) {
    (void)R;
    return 0;
}

static const INPUT_BACKEND gTemplateBackend = {
    .Poll = TemplatePoll,
    .KeyboardDequeue = TemplateKbdDequeue,
    .KeyboardSetLeds = 0,
    .MousePresent = TemplateMousePresent,
    .MouseDequeue = TemplateMouseDequeue,
};

static int TemplateProbe(const TOY_DRIVER *Self, void *BusCtx, void **OutPrivate) {
    (void)Self;
    (void)BusCtx;
    /* TODO: 扫 PCI / 口 / MMIO；有设备则 gTemplateReady=1; *OutPrivate=…; return 0; */
    if (OutPrivate) {
        *OutPrivate = 0;
    }
    return -1; /* 模板默认不上线 */
}

static int TemplateBind(TOY_DRIVER_INSTANCE *Inst) {
    (void)Inst;
    if (ToyDriverInputReady()) {
        return -1; /* 单槽：已有 Input 则失败 */
    }
    return ToyDriverInputAttach(&gTemplateBackend);
}

static void TemplateRemove(TOY_DRIVER_INSTANCE *Inst) {
    (void)Inst;
    gTemplateReady = 0;
}

static const TOY_DRIVER gTemplateDriver = {
    .Name = "template-input",
    .Class = TOY_DRIVER_CLASS_INPUT,
    .Match = 0,
    .Probe = TemplateProbe,
    .Bind = TemplateBind,
    .Remove = TemplateRemove,
};

void TemplateDriverRegister(void) {
    (void)ToyDriverRegister(&gTemplateDriver);
}
```

`_template/README.md` 以 **5 步开篇**，约 **30–50 行**（PR-D-tpl-1 落盘），结构固定为：

1. 写一个 ToyOS 驱动（5 步）  
2. 三种 Probe 匹配模式（PCI / MMIO / 固定口）短例  
3. 三种 Backend 挂载（Input / Block / Net）  
4. 常见错误 + 禁止项  
5. 进阶链接：`InputPs2.c` / `InputXhci.c` /（未来）`驱动开发指南.md`

新人打开 README 即可动手，不必先翻完整设计稿。

## 3. Demo 设计预览（PR-D-tpl-2，本刀不实现）

| 项 | 规格 |
| --- | --- |
| 路径 | `HAL/X64/Drivers/DemoDriver.c`（通配自动编入） |
| Name | `"demo-driver"` |
| Class | `INPUT` |
| Probe | **恒返回 0**；串口 `demo: probe called` |
| Bind | **永远不**调用 `ToyDriverInputAttach`；`return 0`；串口 `demo: bind called` |
| Remove | 空（未 Attach，无需清 Backend） |

**冲突处理（决策）**：Demo 的 Bind **永远不** Attach Input Backend，只占 Driver 实例槽，保证 `lsdev` 可见 `demo-driver input`，且不影响真键鼠。这比「Input 已就绪就不 Attach」更简单、更可预测（避免 QEMU 上 xhci 未起时 Demo 抢槽）。

Demo 的 Probe / Bind 各打一行串口日志（`HalSerialWrite`）：`demo: probe called` / `demo: bind called`，与 `lsdev` 输出对应。

**编译开关**（`HalDevices.c`，include 之后、`HalDriverRegister` 之前）：

```c
#ifndef TOY_DEMO_DRIVER
#define TOY_DEMO_DRIVER 1
#endif
```

注册（保留现有 `MscDriverRegister` 等，勿删）：

```c
void HalDriverRegister(void) {
    AhciDriverRegister();
    AtaDriverRegister();
    NvmeDriverRegister();
    MscDriverRegister();
    InputXhciRegister();
    InputPs2Register();
    NetDriverRegister();
    E1000DriverRegister();

#if TOY_DEMO_DRIVER
    DemoDriverRegister(); /* PR-D-tpl-2：课堂 Demo；-DTOY_DEMO_DRIVER=0 可关 */
#endif
}
```

注意：未定义宏时 `#if TOY_DEMO_DRIVER` 求值为 0，会**关** Demo；因此必须先 `#ifndef` 默认成 1。

验收见 §7（含串口、NUC 键鼠、关开关复测）。

## 4. 新人 5 步（操作清单）

对照现状分析 §7；本设计把路径钉死：

| 步 | 动作 | 易错 |
| --- | --- | --- |
| 1 | 复制 `_template/Template.c` → `HAL/X64/Drivers/MyDriver.c` | 留在 `_template/` 下不会编进 |
| 2 | 改 `Name`、符号前缀、`MyDriverRegister` | 与已有 Name 冲突仅影响 `lsdev` 辨认 |
| 3 | 实现 `Probe`（有设备 return 0） | Register ≠ 上线；还要 ProbeClass |
| 4 | `HalDriverRegister()` 加一行 `MyDriverRegister();` | 忘了则永远不登记 |
| 5 | `./build.sh` → QEMU → `lsdev` | Bind 失败则无输出；看串口 `driver: registered=… bound=…` |

INPUT 以外类：

- **BLOCK**：Bind → `ToyDriverBlockAttach`（见 `BlockAhci.c` 等）  
- **NET**：Bind → `ToyDriverNetAttach`  
- **DISPLAY**：枚举已有，现网无驱动；模板柱不强制 Demo DISPLAY  

指南刀（PR-D-tpl-3）把上表扩成 ≤5 页独立页，并链到技术手册 III、`_template/README.md`、本文。

## 5. 与注册 / Probe 时序的关系

```text
InitializeDriver
  → HalDriverRegister()     # 含（未来）DemoDriverRegister；只 Register
  → ToyDriverProbeClass(BLOCK)

（VMM 后）
  → Input / Net / Block 再 ProbeClass
```

- Demo / 新人 INPUT 驱动：依赖 **INPUT 的 ProbeClass** 路径（与 ps2/xhci 相同轮次）。  
- 模板默认 Probe=-1：即使误注册也不会 Bind。  
- Demo Probe=0：在 INPUT Probe 轮次拿到实例；Bind 不挂 Backend。

不改动 `ToyDriverProbeClass` / `BusCtx`（仍传 0）。

## 6. 匹配规范（PR-D-tpl-4）

三模式仅文档推荐，**不强制**改真驱动；**本柱不实现表驱动匹配**，`TOY_DRIVER.Match` **仍是占位**。正文：[`驱动匹配规范.md`](../驱动匹配规范.md)。

| 模式 | 做法 | 现状代表 |
| --- | --- | --- |
| A 固定口/MMIO | Probe 内直接访问 | `ata-pio`、`ps2-kbd`、virt MMIO |
| B PCI 扫 class/VID | Probe 内枚举 | `ahci`、`nvme`、`xhci-hid`、`e1000` |
| C 软条件 | VMM / 策略位 | `usb-msc` |
