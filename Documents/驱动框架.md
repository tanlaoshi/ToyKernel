# ToyOS 简单驱动框架（Drv）

> 目标：**别人加设备 ≈ 实现一小份 ops + 注册一行**，不改 Common 业务（Gui/FAT）。排期见 [`路线图.md`](路线图.md) **1.3d**；分层见 [`架构分层.md`](架构分层.md)。

---

## 1. 问题与原则

**现状**：`Hal*` 门面 + `HAL/<Arch>/Drivers` + `BlockRegisterBackend` 已能跑；新人加设备仍常要改 HAL 多处。

**原则**（保持简单）：

- 同步调用；无复杂电源管理 / 完整 DMA API
- 总线先做：**virtio-mmio** + **PCI 最小枚举（x86）**；Arm/RiscV 用 **DTB 兼容串**匹配
- 驱动代码仍在 `HAL/<Arch>/Drivers/` 或按类分目录的 `Drivers/`，**经 Drv 注册进类**
- Common **禁止** include 驱动私有头（延续架构分层）
- Common 业务继续只见 `Block*` / `HalInput*` / `HalNet*` / `HalVideo*` 等门面

---

## 2. 模型草图

```text
Probe（总线或 DTB）
  → Match（兼容 ID / virtio device id / PCI id）
  → Bind（分配实例）
  → DrvOps（read / write / ioctl …）
  → 设备类（Block / Input / Net / Display）
  → 现有 Hal* 门面（HalBlock / HalInput / HalNet / HalVideo）
```

| 概念 | 说明 |
|------|------|
| `TOY_DRIVER` | 驱动描述符：名、匹配表、`Probe`/`Bind`/`Remove`、类标签 |
| `ToyDrvRegister` | 启动时或模块表中注册描述符 |
| 实例 | Bind 后的每设备对象；生命周期随 Remove |
| 类适配 | 类层把 DrvOps 接到现有 `BlockRegisterBackend` 或 `Hal*` |

---

## 3. 与现有代码的关系

| 现有 | Drv 之后 |
|------|----------|
| `BlockRegisterBackend` | Block 类适配层内部调用；FAT/VFS 仍只见 `Block*` |
| `HalBlockInit` / ATA / virtio-blk | 迁为 Block 类后端（**D2**），对外行为不变 |
| `HalInput*` / virtio-keyboard | Input 类范例（**D3**） |
| `HalNet*` / virtio-net | Net 类范例（**D3**） |
| `HalVideo*` / ramfb / GOP | Display 类可后置；先不强迫迁完 |

VFS（**1.3f F1**）应挂在 Block/类设备之上，避免 FAT 写死某一种后端。

## 4. 建议目录

```text
Include/Drv.h              # 描述符、注册、类枚举（Common 可依赖的公开面）
Common/Library/Drv.c       # 注册表、Probe 调度（无硬件细节）
HAL/<Arch>/Drivers/        # 具体驱动（ATA、VirtioBlk、VirtioNet…）
  或 Drivers/Block/ …      # 若按类分目录，仍只经 Drv 注册，不进 Services 直链
```

文档范例：「写一个 virtio-xxx」（**D3** README）应包含：匹配 ID、实现哪些 ops、如何 `ToyDrvRegister`、如何用 `lsdev` 验收。
