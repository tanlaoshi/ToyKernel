# ToyOS 驱动匹配规范

> **PR-D-tpl-4**（可选，只文档；TG `e5c700e`）。  
> 操作页：[`驱动开发指南.md`](驱动开发指南.md) §4。现状表：[`../Done/驱动框架现状分析.md`](../Done/驱动框架现状分析.md) §6。  
> API：[`Include/Driver.h`](../../Include/Driver.h)。

本文把现网已经在用的 **三种 Probe 匹配模式**写清楚，并标明哪些是推荐、哪些本柱**明确不做**。

---

## 0. 硬约束（不强制）

| 项 | 结论 |
| --- | --- |
| **不强制**改真驱动 | 已有 `ps2-kbd` / `ahci` / `usb-msc` 等 **不必**为了本文去改 Probe 或填表 |
| **本柱不实现表驱动匹配** | 框架 **不**读 `TOY_DRIVER.Match`；**不**做 PCI/DTB 自动分发 |
| `Match` **仍占位** | 头注释写「PCI/virtio/DTB」；现网全部 `.Match = 0` / `NULL` |
| 不改 API | `Probe` / `Bind` / `Remove` 签名不变；`BusCtx` 现网恒传 `0` |
| `_template/` | 仍不编进 Kernel；模板与 Demo 也是 `Match = 0` |

后人若要做表驱动，须另开 PR 定义表布局，并改 `ToyDriverProbeClass`——**不是本文件的工作**。

---

## 1. 现网怎么认设备

启动：`HalDriverRegister()` 只登记；`ToyDriverProbeClass(Class)` 对已注册驱动调 `Probe(Self, 0, &Private)`；返回 0 再 `Bind`。`lsdev` 只列 **Bound** 实例。

匹配逻辑全部写在 **各驱动自己的 `Probe`** 里（以及 Probe 调用的 `*Setup` / `*InitHw`）。框架不根据 `Name` / `Match` 选驱动。

本树 **没有** DTB `compatible` 匹配实现。

---

## 2. 三模式（推荐写法，不强制迁移）

新人拷 `_template/` 后，按设备类型选一种写在 `Probe` 里即可。三种可以叠（例如先查 VMM，再扫 PCI）。

### 模式 A — 固定口 / MMIO

Probe 内直接碰约定地址；没有总线枚举。

| 代表 | 怎么认 |
| --- | --- |
| `ps2-kbd`（`InputPs2.c`） | i8042 口 `0x60`/`0x64`；还要求 VMM 已开、Input 槽空闲 |
| `ata-pio`（`BlockAta.c`） | 固定 I/O `0x1F0` |
| virt `virtio-*`（`HAL/Virt/`） | **固定 MMIO 窗**扫描（`VirtioMmioScan`），**不是** DTB |

草稿：

```c
if (!VirtualMemoryEnabled()) return -1;
if (!Ps2InitHw()) return -1;   /* 或 Ata / VirtioMmioScan */
return 0;
```

### 模式 B — PCI 扫 class / VID+DID

Probe（或它调用的 Setup）扫 PCI；命中后再 map BAR。

| 代表 | 怎么认 |
| --- | --- |
| `ahci` | class `0x010601`，BAR5（`Ahci.c` `AHCI_PCI_CLASS`） |
| `nvme` | class `0x010802`，BAR0 |
| `xhci-hid` | USB class `0x0C03` + ProgIF `0x30` + HID 枚举成功 |
| `e1000*` | VID `0x8086` + DID 表 |
| `virtio-net-pci` | PCI `1AF4:1000` |

草稿：

```c
if (!VirtualMemoryEnabled()) return -1;
if (!AhciSetup()) return -1;   /* 内部 Pci 扫 class/VID */
return 0;
```

### 模式 C — 软条件

Probe **不**证明「这块硬件已可用」，只满足策略（例如必须在 VMM 后、允许登记）。真正认盘/挂 Backend 放到 Bind 之后的显式步骤。

| 代表 | 怎么认 |
| --- | --- |
| `usb-msc`（`BlockMsc.c`） | Probe：VMM 已开则 `return 0`；Bind **不**装 Block Mux；Shell `msc mount` 才 `BlockMscInstall` |
| 课堂 `demo-driver` | Probe 恒 0；Bind 永不 `ToyDriverInputAttach` |

草稿：

```c
if (!VirtualMemoryEnabled()) return -1;
return 0;   /* 上线策略另说，不要在 Probe 里死等热插拔 */
```

Demo 属于 C：为了 `lsdev` 可见，不是为了认真实硬件。

## 3. `TOY_DRIVER.Match` 占位含义

```c
typedef struct TOY_DRIVER {
    const char *Name;
    TOY_DRIVER_CLASS Class;
    const void *Match;   /* 占位；现网不读 */
    int (*Probe)(const struct TOY_DRIVER *Self, void *BusCtx, void **OutPrivate);
    ...
} TOY_DRIVER;
```

预留方向（**未实现**）：PCI ID 表、virtio device-id 表、DTB `compatible` 串。技术手册 III「匹配什么」与此一致。

在实现表驱动之前：

- 继续 `.Match = 0`
- 继续在 `Probe` 里用 A/B/C
- **不要**把随机结构体指针塞进 `Match` 却指望框架去解

---

## 4. 明确不做

- 改写既有真驱动去填 `Match` 表  
- 框架级 PCI / DTB 自动分发（`ToyDriverProbeClass` 仍按 **已注册列表** 逐个 `Probe`）  
- 全体驱动改成可加载模块  
- 本刀改任何 `.c` / `Driver.h`
