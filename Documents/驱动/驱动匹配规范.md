# ToyOS 驱动匹配规范

> **PR-D-tpl-4**（可选，只文档；TG `e5c700e`）。  
> 操作页：[`驱动开发指南.md`](驱动开发指南.md) §4。现状表：[`../已完/驱动框架现状分析.md`](../已完/驱动框架现状分析.md) §6。  
> API：[`Include/Driver.h`](../../Include/Driver.h)。

本文把现网已经在用的 **三种 Probe 匹配模式**写清楚，并标明哪些是推荐、哪些本柱**明确不做**。

---

## 0. 硬约束（不强制）

| 项 | 结论 |
| --- | --- |
| **不强制**改真驱动 | 已有 `ps2-kbd` / `ahci` / `usb-msc` 等 **不必**为了本文去填表；`Match = 0` 仍走旧 `Probe(Self, 0, …)` |
| 表驱动匹配 **已定型**（阶段 2） | `TOY_DRIVER.Match` 类型为 `const DRIVER_MATCH *`；`Match != NULL` 时框架按表过滤未绑定设备，命中则 `Probe(Self, Dev, …)` 并 `DeviceBindDriver`。规格 [`../待做/设备管理器驱动匹配.md`](../待做/设备管理器驱动匹配.md) |
| `Match` 不再是占位 | `NULL` = 旧行为（Probe 自扫）；非 `NULL` = 表驱动。`demo-driver` 已填表示范（见 §3） |
| 不改 API | `Probe` / `Bind` / `Remove` 三参数签名不变；`BusCtx` 对有表驱动为 `DEVICE_NODE *`，旧路径仍 `0` |
| `_template/` | 仍不编进 Kernel；模板仍 `Match = 0`，Demo 已填表 |

## 1. 现网怎么认设备

启动：`HalDriverRegister()` 只登记；`ToyDriverProbeClass(Class)` 对已注册驱动：
- `Match == NULL` → 旧路径 `Probe(Self, 0, &Private)`（驱动自扫 PCI/DTB）；
- `Match != NULL` → 遍历未绑定 `DEVICE_NODE`，`DriverMatchesDevice` 命中则 `Probe(Self, (void *)Dev, &Private)`，成功 `DeviceBindDriver`（一驱动一实例）。

返回 0 再 `Bind`。`lsdev` 只列 **Bound** 实例。

匹配逻辑全部写在 **各驱动自己的 `Probe`** 里（以及 Probe 调用的 `*Setup` / `*InitHw`）。框架不根据 `Name` / `Match` 选驱动。

本树 **没有** DTB `compatible` 匹配实现。

---

## 2. 三模式（推荐写法，不强制迁移）

新人拷 `_template/` 后，按设备类型选一种写在 `Probe` 里即可。三种可以叠（例如先查 VMM，再扫 PCI）。

### 模式 A — 固定口 / MMIO

Probe 内直接碰约定地址；没有总线枚举。

| 代表 | 怎么认 |
| --- | --- |
| `ps2-kbd`（`InputPs2.c`） | i8042 口 `0x60`/`0x64`；还要求 VMM 已开、Input 槽空闲 |
| `ata-pio`（`BlockAta.c`） | 固定 I/O `0x1F0` |
| virt `virtio-*`（`HAL/Virt/`） | **固定 MMIO 窗**扫描（`VirtioMmioScan`），**不是** DTB |

草稿：

```c
if (!VirtualMemoryEnabled()) return -1;
if (!Ps2InitHw()) return -1;   /* 或 Ata / VirtioMmioScan */
return 0;
```

### 模式 B — PCI 扫 class / VID+DID

Probe（或它调用的 Setup）扫 PCI；命中后再 map BAR。

| 代表 | 怎么认 |
| --- | --- |
| `ahci` | class `0x010601`，BAR5（`Ahci.c` `AHCI_PCI_CLASS`） |
| `nvme` | class `0x010802`，BAR0 |
| `xhci-hid` | USB class `0x0C03` + ProgIF `0x30` + HID 枚举成功 |
| `e1000*` | VID `0x8086` + DID 表 |
| `virtio-net-pci` | PCI `1AF4:1000` |

草稿：

```c
if (!VirtualMemoryEnabled()) return -1;
if (!AhciSetup()) return -1;   /* 内部 Pci 扫 class/VID */
return 0;
```

### 模式 C — 软条件

Probe **不**证明「这块硬件已可用」，只满足策略（例如必须在 VMM 后、允许登记）。真正认盘/挂 Backend 放到 Bind 之后的显式步骤。

| 代表 | 怎么认 |
| --- | --- |
| `usb-msc`（`BlockMsc.c`） | Probe：VMM 已开则 `return 0`；Bind **不**装 Block Mux；Shell `msc mount` 才 `BlockMscInstall` |
| 课堂 `demo-driver` | Probe 恒 0；Bind 永不 `ToyDriverInputAttach` |

草稿：

```c
if (!VirtualMemoryEnabled()) return -1;
return 0;   /* 上线策略另说，不要在 Probe 里死等热插拔 */
```

Demo 属于 C：为了 `lsdev` 可见，不是为了认真实硬件。

## 3. `TOY_DRIVER.Match` 表驱动（阶段 2 已实现）

```c
typedef struct TOY_DRIVER {
    const char *Name;
    TOY_DRIVER_CLASS Class;
    const DRIVER_MATCH *Match;   /* NULL = 旧行为；非 NULL = 表驱动 */
    int (*Probe)(const struct TOY_DRIVER *Self, void *BusCtx, void **OutPrivate);
    ...
} TOY_DRIVER;
```

`DRIVER_MATCH`（`Include/Driver.h`）按 `Type` 分 PCI / DTB / FIXED，表以 `DRIVER_MATCH_NONE` 结尾；`DriverMatchesDevice`（`Common/Library/DriverMatch.c`）逐条比对：
- **PCI**：`(Vendor & VendorMask)==(entry.Vendor & VendorMask)` 且 `(Device & DeviceMask)==(entry.Device & VendorMask)`；`Mask=0` 即通配；
- **DTB**：`Compatible` 串全等；
- **FIXED**：`Bar[0]==entry.Base`。

`demo-driver` 示范（`HAL/X64/Drivers/DemoDriver.c`）：匹配任意 Intel PCI 设备（`Vendor=0x8086` 精确、`Device` 通配），枚举序首张 = QEMU 宿主桥 `0x8086:0x1237`，`Probe` 收到非空 `BusCtx`（`DEVICE_NODE *`），`Bind` 占实例槽使 `lsdev` 可见。

旧驱动继续 `.Match = 0` 走 A/B/C；**不要**把随机结构体指针塞进 `Match`——必须是 `DRIVER_MATCH[]`。

---

## 4. 明确不做

- 改写既有真驱动去填 `Match` 表（`demo-driver` 之外不迁；xhci 另刀）  
- 全体驱动改成可加载模块  
- 一驱动多设备（一驱动一实例，另柱）
